从递推接上：已知的小答案怎样帮忙

这一站带走：能说清递推的起点、关系和计算顺序。

递推像铺一条石板路：先站稳第一块，再用已经知道的结果铺下一块。

定义 S(n) 为 1 到 n 的和，约定 S(0)=0。从已经知道的 S(n−1) 出发，再加上新来的 n，就能得到 S(n)。这个联系叫递推关系。

正在求谁已知谁这次增加什么
S(0)不依赖其他项直接约定起点
S(1)S(0)1
S(2)S(1)2
S(3)S(2)3

顺着 n=1、2、3……计算，就是这里的递推实现。实际只想要最后一个和时，一个累加变量就够了；需要查询每个前缀的和时，才有理由保存整张表。

// 自己补两处，让变量与定义一致
s[0] = ___;
for (int i = 1; i <= n; ++i) {
    s[i] = ___;  // 用已经算好的那一项
}
换一个起点，整条路可能都不同
台阶题的 ways(0)=1 表示“什么都不走”也算一种方案；求和的 S(0)=0 表示空集合的和为零。边界来自函数含义，不能见到 0 就机械返回 0。

递推与递归，怎样相遇？

同一个 S(n)，可以“从 0 一路算上来”，也可以“为了求 n，先请求 n−1”。前者主动安排计算顺序；后者让函数调用组织依赖。同一个数学关系，常常能用不同程序表达。递推不等于所有循环，递归也不等于所有动态规划。

递归的第一张任务卡

这一站带走：用“含义、停止、小任务、收尾”描述一个递归。

递归：一个函数在完成任务时，调用它自己，去做一个同类的子任务。

“自己调用自己”听起来像绕圈。关键区别是：每次交出去的任务要朝着能直接解决的情况靠近。像打开一套套娃，里面还有小套娃，但最里面那只可以直接拿出来。

继续用 S(n)。这次你只负责最大的一层：你想求 1 到 n 的和，可以请助手求 1 到 n−1 的和。助手交回结果后，你还有一件自己的事要做。

任务卡上的四格这道示范任务
含义 / 契约sum(n)：输入非负整数 n，返回 1 到 n 的和
停止 / 边界没有数要加时，直接给出空和
小任务 / 分解请同一个函数处理少一个数的情况
收尾 / 合并把自己这一层剩下的数放回结果
// 练习骨架，不是可直接提交的程序
long long sum(int n) {
    if (n == 0) return ___;
    long long smaller = sum(n - 1);
    return ___;
}

smaller 的含义不是“随便存个数”：它专门记录子任务交回的结果。先用中文说它是谁，代码里的加法才有依据。

一层只负责一层
设计时可以暂时相信“小任务会按约定完成”，把这一层的工作想清楚；验证时再检查边界、缩小和合并。这是有依据的分工，不是盲目相信。

求和用循环更直接。我们选择它，是因为题意简单，可以把注意力留给调用机制。递归真正有吸引力的地方，是后面那些天然分成子任务的问题。

栈是什么？它怎样帮函数记住回来的路

这一站带走：能说清栈的存取规则、调用栈保存的信息，以及递归返回时怎样继续。

先把三个问题分开：什么是栈？函数为什么需要它？递归与它有什么关系？

这三个问题可以分三次学。先把第一步说清，再进入下一步。本页用“工作单”模拟普通、同步函数调用；它帮助理解执行顺序，不是在画实际内存布局。

① 栈：怎样存、怎样取② 普通函数：记住做到哪儿③ 递归：同名函数，多张工作单
第一步 / 先不谈递归

栈，是一种有存取规则的数据容器。

电脑要把一些数据存起来，之后再使用。除了问“存了哪些数据”，我们还要约定“从哪里放进去、从哪里取出来”。栈（zhàn）的规则是：放入和取出都只在同一端进行。这一端叫栈顶。

另一端叫栈底。放入一个新元素叫入栈；移除栈顶元素叫出栈。栈里存的可以是数字，也可以是一张包含好几项信息的记录。人们把这种“组织数据并规定操作方式”的东西叫作数据结构。

先记这一句就够
栈里可以放很多东西，但下一次只能取走最后放入、而且还没取走的那一个。这叫后进先出。栈不会替你计算答案，它只按规则保管数据。

把规则画出来，不靠想象

下面从左向右写一排数字，右端是栈顶。开始没有任何数据，记成 []。看一遍演示后，请自己重新画一遍。

这次操作操作后的栈：左底 → 右顶这一刻能取谁？
放入 40[40]40
再放入 7[40, 7]7；不能越过它取 40
再放入 25[40, 7, 25]25
取走一个[40, 7]现在轮到 7；刚才移除的是 25
只看栈顶，不取[40, 7]仍然是 7，数量不变

为什么先取 25？因为它最后放入，不是因为它最大或最小。栈按放入顺序管理数据，不是按数值大小排序。如果是普通数组，你可以用下标访问不同位置；使用栈的规则时，不提供“随意拿走中间那个”的操作。

第二步 / 先看三个不同的函数，没有递归

调用另一个函数时，原来的函数还没做完。

设想有三个函数：A 要用 B 的结果，B 要用 C 的结果，C 可以直接给出 3。下面是任务说明，暂时不用写 C++：

A 的两步B 的两步C 的一步
A① 请 B 给一个数，放进自己的 xB① 请 C 给一个数，放进自己的 xC① 直接返回 3
A② 返回 x + 10B② 返回 x × 2完成后没有别的事

A 执行到第一步，B 还没回答，A 的 x 就还没有赋上结果，A②也不能开始。于是先暂停 A，转去执行 B。B 又要等 C，于是暂停 B，转去执行 C。

暂停不是忘记：必须留下三类信息

假如你做作业中途去找一本书，会记住“正在做哪一题、已经算出了什么、回来从哪儿继续”。函数暂停时也有类似需要。我们给每次调用画一张工作单：

A 这一次调用的工作单

① 身份：我是 A 的这一次调用。

② 本层数据：我的 x 还在等 B 的返回值。

③ 继续位置：B 回来后先完成 A①，给 x 赋值；然后执行 A②。

对更一般的函数，还要保存这一层的参数等信息。这些属于一次调用的工作信息，在这里统称为栈帧。现在记作“工作单”就可以。返回位置是要记录的信息，具体怎样放在机器内存里不影响这一教学模型。

为什么这些工作单适合放在栈里？

A 等 B，B 等 C。在这条嵌套调用链上，必须先完成 C，再让 B 继续，最后才轮到 A。新调用开始时把它的工作单放到顶端；它结束时撤掉顶端工作单，下面刚刚暂停的调用就能继续。

这恰好就是“后进先出”。用栈来保存这些尚未结束的调用记录，就叫调用栈。它让程序能找到“刚才是谁在等我，以及它等到哪一步”。

A② 返回 x + 10

B② 返回 x × 2

调用栈 · 栈顶在上

“取出工作单”与“交回返回值”是两件事
C 交回的数是 3；C 的工作单随后结束使用。程序不是把“C 这张单”当成答案。露出 B 的工作单后，B 先把收到的 3 存入自己的 x，再从 B②接着算。

先证明自己看懂了普通调用

  1. C 正在执行时，A 和 B 是结束了，还是暂时等着？
  2. C 返回以后，为什么先回 B，而不是直接回 A？B 的 x 与 A 的 x 是同一个吗？
  3. B 交回一个数之后，A 应该从头再调用 B，还是完成 A①再去 A②？工作单哪一栏帮助你判断？
只提示一个位置

盯住每张工作单的“继续位置”。当前工作单撤掉后，露出的那张是谁，就先接着谁未完成的那一步。

第三步 / 现在才把普通调用换成递归

递归没有换一套返回规则，只是调用的函数同名了。

刚才是 A 调 B、B 调 C。现在换成 sum(2) 调 sum(1)，再由 sum(1) 调 sum(0)。这三个任务使用同一份 sum 函数说明，却是三次不同的调用，各有自己的工作单。

这里 sum(n) 承诺返回 1 到 n 的和。为了观察执行，我们把一次调用的工作分成三步：

① 检查边界：n 为 0 时，直接返回 0。
② 否则请 sum(n−1) 完成小任务，把返回值存到本层的 smaller。
③ 交回 n + smaller，完成本层任务。

先只看 sum(2)。它不是把自己的 n 改成 1，而是给新调用传入 1。新工作单写 n=1，原工作单仍写 n=2。下层参数继续变小，上层暂存的参数不会跟着变化。

sum(2) 等待时，要记住什么？

本层 n = 2；smaller 尚未收到。

待办：等 sum(1) 回来，完成第②步的赋值，再在第③步加上本层的 2。

先预测：当 sum(0) 返回 0 时，哪个调用先收到？收到后，它还有哪一步没做？先想，再点下面的实验。

把“递”和“归”接起来

递下去：现在的任务还不能直接答，就保存“本层是谁、还欠什么工作”，创建更小任务的工作单。

归回来：最小任务直接给出结果，工作单结束；上一层接收结果，完成自己的剩余工作，再把结果交给更上一层。

这解释了两件事：为什么回来后还能记得原来的 n——它在本层工作单里；为什么知道下一步做什么——暂停时留下了继续位置。只记“后进先出”而不看工作单内容，就很难看懂递归。

这三个词分别是什么？
栈一种数据结构，规定从同一端放入和取出，后进先出
调用栈把未结束的函数调用记录，按栈的规则组织起来
递归函数调用自身来完成子任务；调用与返回仍遵守普通函数规则

写普通 C++ 递归时，不需要先手写一个 std::stack。理解调用栈，是为了在脑中或纸上模拟程序怎么执行。以后把递归改成循环、自己管理这些工作单时，才需要自己维护栈。

时间复杂度：总共做了多少工作？

这一站带走：先数调用与本层工作，再判断规模增大时工作量怎样增长。

两段程序都能算对，为什么一个很快，另一个越算越慢？先别计秒数，先数它们做了多少事。

同一段程序在不同电脑上，用时可能不同。我们更关心：输入规模 n 变大时，计算工作怎样增加。时间复杂度描述的就是这种增长规律。

第一笔：一次调用只做固定数量的事

回到 sum(n)。除了请求小任务，每层只检查边界、接收结果、做一次加法和返回。n 变大，这些本层动作不会变成一百次、一千次；我们把它们合起来看成一份常数工作。

从 sum(4) 开始，依次出现参数 4、3、2、1、0，共 5 次调用。一般从 n 开始，调用 n+1 次。每次做常数工作，总工作量随 n 大致成正比，记作 O(n)。

O(n) 不是“准确执行 n 条语句”，也不是“用了 n 秒”。n+1、3n+5 都是线性增长；讨论量级时，通常忽略常数倍和较小的项。若某段工作不随 n 增长，就记作 O(1)。

第二笔：每次调用里，还可能有一个循环

// 执行规则：输入是非负整数 k
// k=0 时直接结束；否则：
重复 k 次：做一件常数时间的小事
再请求任务(k-1)
// 这是一条调用链，但每层的工作量不同。

k=4 那层做 4 次，下一层做 3 次，然后 2 次、1 次。循环总次数是 4+3+2+1。一般是 n(n+1)/2，再加上检查、调用等线性开销，主要增长量是 n²，所以时间是 O(n²)。

同样只有 n+1 次调用，时间却未必都是 O(n)。必须把每层自己的工作也算进去。各层工作不同，就逐层相加；不能只数函数调用。

第三笔：每层都请两个助手

设 k>0 时，先后调用两次任务(k−1)，k=0 时结束，每次调用本身只做常数工作。第 0 层有 1 次调用，第 1 层有 2 次，第 2 层有 4 次……第 n 层有 2ⁿ 次，总共 1+2+4+…+2ⁿ=2ⁿ⁺¹−1 次。这种工作量是 O(2ⁿ)。

注意两个子调用是先后执行，并非同时启动。树有多宽影响总工作量；一条路有多深影响同时需要的工作单数量。下一站专门算空间。

空间复杂度：最多同时留下多少东西？

这一站带走：区分累计调用数与同时存活的工作单，并把缓存和数组算进空间。

时间问“总共做了多少事”，空间问“最拥挤的一刻，同时保留了多少东西”。

把桌面当成内存。一个工作单结束后，它原先占的位置可以给后来任务用。因此，不能把程序从头到尾用过的所有工作单都累加，当成同时需要的空间。

先只算调用栈

sum(4) 最深时，sum(4)、sum(3)、sum(2)、sum(1)、sum(0) 还同时存在，共 5 张单。每张只保存固定数量的参数、变量和继续位置，因此额外栈空间随 n 线性增长，为 O(n)。

上一站的“双分支任务”有很多次调用，但先走完左支、返回，再走右支。没有把已结束的记录另外存起来时，同时留着的主要是当前路径。因此虽然时间 O(2ⁿ)，调用栈仍是 O(n)。

再问：每张单上有没有装一个大数组？

若每层只有几个整数，单层空间是 O(1)。若参数为 k 的每层都另外创建 k 个元素的数组，并让它一直保留到本层结束，最深时这些数组都还在：n+(n−1)+…+1 个元素。总空间就可能达到 O(n²)。

如果所有层共同使用同一份长度为 n 的辅助数组，那份数组只数一次。此时是 O(n) 的栈加 O(n) 的辅助数组，仍为 O(n)，并非相乘。

实验室 / 看最拥挤的一刻

都按 n→n−1→…→0 调用。为比较趋势，把一张固定工作单计作 1 格、一个数组元素计作 1 格；格子不是实际字节数。

缓存与结果也会占空间

后面要学的记忆化会把算过的答案存起来。若存 n+1 个答案，就需要 O(n) 的缓存，不能只算递归栈。若把所有子集都保存下来，结果集合也可能很大；只输出一份后不再保留，与保存所有份，不是同一笔空间账。

要找的东西怎么数
调用栈找同时存在的调用；单层大小相同，才能用“最大深度 × 单层空间”
每层私有的大数据沿当前路径累加仍保留的数据，不要假定每层都是 O(1)
共享数组、缓存每份实际存储只数一次，再与栈空间相加
保留的全部答案按照方案数量与每份大小计算；不保留就不要虚构这项

本讲主要讨论辅助空间，即算法额外使用的空间。若题目问总内存，还要加上输入本身与保留的输出。写分析时说清自己的统计口径，比只写一个 O 更重要。

换成循环，空间也要重新算
简单累加改为循环，可能只需几个变量，辅助空间降到 O(1)。复杂任务改用显式栈，仍要保存未完成的工作单，并不自动变成 O(1)。

同一个问题，还可以从小到大算

两份一样的请求，也要算两遍

如果写成“请求 half 一次 × 再请求 half 一次”，普通函数不会自动记住第一次结果。递归深度仍是 O(log b)，但重复分支会把工作量放大。保存 half 的写法对 b≥1 用 O(log b) 次乘法；b=0 是常数时间。

区间的另一种对半切

处理闭区间 [l,r] 时，可分成 [l,mid] 与 [mid+1,r]，其中 mid=l+(r-l)/2。当只剩一个元素时不要再拆；否则左半区间可能和原区间一模一样。先画出长度为 1、2、3 的区间，再写递归。

实际大数怎么办？
若题目要求模 m，要在乘法与合并时取模；但“乘完才取模”也可能先溢出。需要结合数据范围选择类型与乘法方法。此处先限定小数值，后续再把数值安全作为独立检查。

为什么“都减半”也可能差很多？

每层只求一次 half，任务规模沿着 b、⌊b/2⌋、⌊b/4⌋……变小，到 0 只需 O(log b) 层（b≥1）。每层常数工作，所以时间也是 O(log b)。

若相同的小任务请求两次，调用会分叉。对这个指数减半、两支相同的模型，普通重复递归的时间为 O(b)，深度仍为 O(log b)。参数减半只说明路径短，不保证整棵调用树的工作也少。先数分支，再判断时间。

怎样选择优化：先找到浪费在哪里

这一站带走：说清某种优化省了什么、付出什么，以及为什么不改变答案。

“递归太慢”还不是诊断。先问：它究竟把时间或空间花在哪里？

前面见过几种办法：把已经完成的子任务结果记下来、复用一个中间结果、让任务更快变小、跳过没有希望的分支。现在把它们放到一起比较。

同一个求和任务，比较两笔账

递归逐次求和与循环累加，都要处理 n 个数，时间都是 O(n)。普通递归保留 O(n) 层工作单；循环只要“加到哪里、当前总和”这几个变量，辅助空间可以是 O(1)。

所以“改成循环”在这个例子里主要省下了调用栈和调用开销，没有把 O(n) 的时间变成 O(1)。若某个搜索仍然要枚举 2ⁿ 种选择，换一种写法也不会自动消除这些选择。

记忆化为什么常被说成“用空间换时间”？

普通斐波那契递归会重复计算，记忆化保存不同状态的答案，把时间从指数级降到线性。代价是缓存表。普通版自身已经需要 O(n) 栈，所以两者总辅助空间的量级可以同为 O(n)，但记忆化确实多存了一份答案表。不要只看到大 O 相同，就说“没有增加任何存储”。

选学 / “尾递归”是什么意思？

如果一次递归调用已经是当前函数最后要做的事，回来以后只把它的返回值原样交回，这种位置叫尾调用；调用自身时叫尾递归。例如局部形式 return f(n-1, acc+n); 把累计工作带进参数。相比之下，return n + f(n-1); 还要等返回后做加法。

尾递归是否被编译器消除调用栈，不能在普通 C++ 程序里一概保证。若确实需要控制栈空间，应自己写成可验证的循环，并检查边界与状态更新；不要把“长得像尾递归”当作空间安全的证据。

优化前后，要拿同一把尺子量

  1. 保留小规模正确版本，作为对照。

分治的合并现场：归并与逆序对

这一站带走：理解子任务只负责内部，父任务负责跨两边的信息。

把任务拆开容易，难点常常在于：两边都完成后，如何接成完整答案？

归并排序约定：sort(l,r) 把闭区间 [l,r] 排好。只有一个元素时已然有序；否则把左右区间分别排好，再把两条有序队伍合成一条。把左右两段直接拼起来，不代表整体有序。

再多问一步：原来有多少逆序对？

逆序对是原数组中 i<j 且 a[i]>a[j] 的一对位置。每对位置只有三种归属：全在左边、全在右边、左一个右一个。前两类交给子任务，跨两边的由本层合并时统计。

假设左右已排好。当左边当前值大于右边当前值，左边从当前指针到末尾都比它大，可以一起计数。相等不算逆序；使用“相等时先取左边”的规则更容易保持计数条件正确。

合并结果 / 跨区间逆序数

为什么不会重复数？

一对位置被左右分开的那一次合并，负责统计这对跨区间关系。它们在更小区间里还没同时出现；更大区间则把它们看成同一侧内部的关系。为每类贡献指定负责层，是分治计数的重要方法。

每一层合并总共处理 O(n) 个元素，约有 O(log n) 层，所以时间 O(n log n)。共用辅助数组 O(n)，递归栈 O(log n)。当 n=200000 时，逆序对最大值 n(n−1)/2 已超出 32 位有符号整数，要先提升类型再乘。

树形 DP：一张工作单带回两种答案

这一站带走：学会让状态携带父任务真正需要的条件，理解树形最优选择。

孩子只汇报“我这里最大能得到多少”，有时不够。父亲还要知道：这个最大值用了谁？

一棵树，每个节点有非负价值，相邻两个节点不能同时选。目标是使所选节点价值总和最大，允许一个也不选。这叫树上的最大权独立集模型。

看最小冲突：父节点价值 9，唯一孩子价值 8。如果孩子只回报“最多 8”，父亲把自己的 9 加上去，就违反相邻限制。所以任务卡需要把根节点选 / 不选分开。

状态准确含义父节点能利用什么
dp[u][0]u 不选时，u 的子树内最大合法价值孩子选或不选都可能允许
dp[u][1]u 选时，u 的子树内最大合法价值相邻的孩子根必须不选

对于每个孩子 v，如果 u 已经选了，v 的两种状态里哪种合法？如果 u 没选，是否可以为这个孩子挑更好的那一种？不同孩子的子树之间没有边，这一点为何关键？

我已经推过了 · 核对这一个局部转移

u 选：初值是 w[u]，对每个孩子加 dp[v][0]。u 不选：初值是 0，对每个孩子加 max(dp[v][0],dp[v][1])。根节点没有上层限制，最后比较根的两种状态。这里用“最大值”而非“方案数”的加乘法，因为任务是最大化价值。

叶子没有孩子，两个初值已经是完整答案。不同孩子的选择彼此不冲突，才能分别选优再相加。

延迟标记：登记的承诺，不是忘记更新

若要把整个 [l,r] 每个数都加 d，节点总和可立即增加 d×(r−l+1)。同时记下一个“这段的孩子还欠着加 d”的标签。以后必须深入孩子时，才把这份承诺下发；下发后清掉父节点已传递的标签。

用四个数 [1,2,3,4] 看这件事。管理全段的父节点原来记总和 10；若四项都加 2，父节点可以马上把总和改成 18，同时记下“孩子还没加 2”。它的左孩子仍可能记着前两项的旧和 3，右孩子仍记着旧和 7。

此时查询整段，直接回答父节点的 18 就对了。但若只查前两项，就不能直接拿左孩子的旧和 3：进入孩子前，先把父节点记录的“每项加 2”传下去。左孩子有两项，总和增加 4，变成 7；右孩子也增加 4，变成 11。孩子若还有下一层，也记下自己尚未传下去的增加量。父节点的标记已传完，可以清除。

因此每一步都要保持这个约定：本节点保存的和，已经包含自己的增加量；更下层可能还需要接收标记。查询整段用本节点的和，查询其中一部分则先传递标记，再进入孩子。这就是前面所说的延迟：推迟逐层处理，同时把还没传下去的修改记清楚。

我已理解区间加 · 再看标记组合

连续“加 2，再加 3”可以合成“加 5”。但“赋值为 2，再加 3”和“加 3，再赋值为 2”效果不同。延迟标记必须定义运算顺序，不能把区间加的模板直接用于区间赋值。

标准二叉线段树建树 O(n)，区间求和、单点修改，以及带正确加法标记的区间加通常为 O(log n)，存储 O(n)，递归深度 O(log n)。这与“递归一定很慢”相反：关键是每次访问多少节点。

折半搜索：把大选择拆成两边

这一站带走：把完整方案拆成两半，比较枚举和匹配的资源开销。

剪枝遇到不好剪的数据，仍可能走遍整棵树。能不能改变枚举与组合的方式？

输入 n 个非负整数重量，每件最多选一次，问能否恰好凑出 T。这里关注 n≤40、重量与 T≤10⁹ 的情况。直接枚举约有 2⁴⁰ 个子集；把物品分成两半，每半最多 20 个，先分别枚举各半的全部子集和。

一个完整子集，可以唯一拆成“左半选了哪些 + 右半选了哪些”。如果左边的和是 x，就去右边找是否存在 T−x。这叫折半搜索。能这么拆，不代表所有题都能仅靠一个“和”组合；这里的限制只依赖总重量。

用四件物品，把这座桥自己搭起来

重量为 [2,5,3,7]，目标 T=10。左边用 [2,5]，右边用 [3,7]。请分别列出两边所有子集和，别忘空集的和是 0。再为每个左侧 x 查右侧所需的 T−x。

省了枚举，也增加了存储和匹配

每边约有 2²⁰ 个和。把右侧排序后，为每个左侧和二分查找，时间可用 O(n·2⁽ⁿ⁄²⁾) 作上界，存储 O(2⁽ⁿ⁄²⁾)；这里只用 n 为偶数的写法表示量级，奇数时两边相差一个元素。

一百万个 64 位整数，仅元素存储就约 8 MB；两个列表及额外开销都要估计。递归枚举每半的栈深度是 O(n)，但保存的和列表才是这里更大的空间项。

问题问法决定匹配规则
问“是否存在”，找到一次匹配就能宣布存在；问“有几种选法”，相同的和可能来自不同编号子集，不能随便去重，也不能找到一次就停止。先确定输出是什么。

折半方法把指数中的规模减半，却没有把问题变成普通的线性算法。n 再大很多时，仍然要重新考虑资源与其他方法。

记忆化再升级：状态必须够用

这一站带走：能判断两个请求是否真的等价，而不是只看函数名字一样。

能否缓存一个答案，取决于两次任务是不是同一个问题。

先看简单例子：从物品 i 往后，剩余容量为 rest，最多还能得到多少价值？solve(i,rest) 至少需要把 i 与 rest 都放进缓存键。只按 i 保存，就把“背包还有很多空间”和“已经装满”混为一谈。

新场景：逐位构造数字

给定 0≤N≤10¹⁸、0≤K≤162，数一数 [0,N] 中数位和恰好为 K 的整数。这里把 0 的数位和约定为 0。把 N 写成数字数组，从最高位开始逐位选择。递归像给每个位置选择一颗数字宝石。

状态为什么需要
pos下一个要填写的数位位置
sum当前已经选定的数位和
tight前缀是否仍与 N 的前缀完全相同；若相同，本位不能超过 N 对应位
固定上下文本次 N 与 K；换一道查询时旧缓存通常不能直接复用

为了让每个数只对应一种表示，统一补前导零到 N 的位数。对于“数位和”任务，前导零不改变数位和，因此无需单独的 started 标记。若改成“十进制表示中不能出现数字 0”，前导补的零是否算真正数字，就必须重新定义状态与规则。

先想两个前缀

N=325。同样走到第二位，前缀是 3 时仍受上界限制；前缀是 2 时，后面可以自由选择 0 到 9。若只记 pos 和 sum，是否可能复用一个不适合当前限制的答案？

我已推过状态 · 核对缓存边界

固定 N、K 后，可以缓存完整 (pos,sum,tight)，也常只缓存 tight 为假的自由状态。终点按 sum 是否等于 K 贡献 1 或 0；sum>K 可提前停止，因为之后只加非负数字。计数必须使用足够大的整数类型。

对于 D 位、sum≤K 的状态，每个枚举 10 个数字，时间上界 O(D·K·10)，缓存 O(D·K)，栈深度 O(D)；把 K=0 等边界写成 O(D·(K+1)·10) 更完整。这才是“状态数 × 每状态工作量”的真正用法。

D. 树上营地

输入 n（1≤n≤200000），n 个非负价值（≤10⁹），再输入 n−1 条无向边，保证形成一棵树。相邻节点不能同时建营地，允许不建，输出最大总价值。

手推树：边 1—2、1—3；价值分别为 5、4、4。测试类别：单节点、星形、长链、全零。对照法：n≤18 时枚举所有子集判断相邻冲突。

提示 · 父亲需要知道什么？

如果根节点被选，孩子返回的“最大值”还能无条件使用吗？先给状态加上必要的限制，再考虑遍历方式。

Ⅳ · 提高组合 / 树上背包

E. 恰好 K 个营地

沿用 D 的相邻限制，改为必须恰好选 K 个。输入 n、K（1≤n≤200，0≤K≤min(n,30)），n 个非负价值（≤10⁶），再输入 n−1 条树边。输出最大价值；没有合法方案时输出 IMPOSSIBLE。

手推树：三节点链，价值 2、100、2，分别考虑 K=1、2、3。测试类别：K=0、不可能、多个孩子需要分配名额。

提示 1 · 一个“最大值”不够了

状态需要同时知道根选不选、恰好选多少个。无法做到的数量，不能当成价值 0。

提示 2 · 合并一个孩子

枚举“已处理部分选 a 个，当前孩子选 b 个”，合并到 a+b 个。用新数组或谨慎的合并顺序，防止同一孩子被重复利用。父根选中时，孩子根允许哪个状态？

提示 3 · 资源账单

用朴素的数量枚举合并，可给出 O(nK²) 时间上界、O(nK) 状态空间。不可达值应单独标记或设为负无穷，参与加法前先判合法。

Ⅳ · 提高综合 / 区间结构

F. 能量走廊

输入 n、q（各 1…100000）及 n 个初值。随后 q 行操作：ADD l r d 将闭区间每个数增加 d；SUM l r 输出区间和。保证 1≤l≤r≤n，初值与 d 的绝对值≤10⁴。

手推操作：从 [1,2,3,4] 开始，先 ADD 1 4 2，再 ADD 2 3 −1，最后 SUM 2 4。测试类别：全段加后查单点、重复相交修改、负增加、n=1。对照法：小数组逐格修改。

提示 · 给标记写一句承诺

说明节点总和已包含什么、孩子还欠什么。再决定完全覆盖时怎样处理、部分覆盖时什么时候下发、回来后什么时候重算。
