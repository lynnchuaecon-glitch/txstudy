01 / 30A · 从零到单链表

一条队伍，不一定挤在一起

这一站带走：从卡片与箭头理解“后一个是谁”。

先修：数组、循环、函数；不预设学过链表

把队伍记下来，可以记座位，也可以记伙伴。

三位同学按小鹿、小熊、小兔排队。用数组表示时，我们常把第 1、2、3 个位置依次存好。另一种办法：每个人拿张纸条，写“我后面是谁”；再用一张入口卡记“第一个是谁”。桌上卡片怎样摆都可以，队伍的顺序由纸条决定。

入口 → 小鹿 → 小熊 → 小兔 → 结束

这样的卡片叫结点。结点至少要存两件事：自己的数据、下一个结点的位置线索。线索叫链接；图上画成箭头。最后一个没有后继，需要专门的结束标记。

让小猫站到小鹿后面时，目标是让箭头表达新队伍。小兔的卡片无需搬家。今天只动卡片，不写 C++，也不需要认识内存地址。

02 / 30A · 从零到单链表

编号、位置、数值：三个不同的名字

这一站带走：把结点身份与当前排名分开。

先修：第 1 站

搬到队首，不会让你的身份证号码变成 1。

给结点分配固定编号：4 号存值 8，1 号存值 5，7 号也存值 8。入口指向 4，链接为 4→1→7。4 号是队伍中的第 1 个；它的编号是 4，值是 8。这三个数承担不同职责。

固定编号 id数据 value当前第几个
481
152
783

把 7 号移到最前面后，它仍是 7 号，值仍为 8；只有排名变了。两位同学可以同名，两个结点也可以同值，所以“删除值为 8 的结点”还需要说明删第一个还是全部。

之后的数组模拟，用编号当数组下标。nxt[4]=1 表示 4 号的后继是 1 号，绝不表示 4 号后面还有 1 个人。数组编号可以跳跃，不能用 id++ 代替沿链接走。

03 / 30A · 从零到单链表

变量登记表：谁保管入口，谁负责走路

这一站带走：把程序变量翻译成队伍中的角色。

先修：第 1～2 站

带路的人向前走，入口牌不能跟着丢。

把入口记作 head，用 cur 表示现在正在看的结点，nxt[id] 存后继编号。为了避免与真实结点混淆，前半讲统一保留编号 0 表示“没有结点”，真实结点从 1 开始。

角色初值什么时候变
head：第一个结点空表为 0首结点改变
cur：当前访问位置head访问完向后走
nxt[id]：id 的后继按队伍连接插入、删除或改序
value[id]：结点数据读入的数据题目要求改值时
used：已分配最大编号0分配新结点时加 1
size：活跃结点数量0实际插入加 1，实际删除减 1

后面若不需要快速报告数量，可以不存 size。每增加一个变量，就增加一项需要维护的承诺。used 与 size 也不一样：删除通常不会让已分配编号倒退。

本讲的记号约定

nxt、pre 是数组字段；next、prev 是指针结点字段。例子切换表示时会说明。0 是数组模拟的空编号，不是一张可以输出的数据卡。

04 / 30A · 从零到单链表

用数组造出第一条链

这一站带走：理解数组模拟链表的存储与连接。

先修：第 2～3 站

房间连续编号，队伍仍可以拐着走。

开两个等长数组 value 和 nxt。同一个下标合起来表示一个结点；先给数据，再建立链接。例子用 1、2、3 三个槽位，但队伍为 2→3→1。

编号valuenxt
1300
2103
3201
head=2 → [2号:10] → [3号:20] → [1号:30] → 0

这常叫数组模拟链表 / 静态链表。存储仍是数组，逻辑顺序却由 nxt 决定。这里“静态”描述存储方法，和 C++ 的 static 关键字不是一回事。

真实操作里常按分配顺序使用新编号：每次取一个从未使用的槽位。若最多有 n 个初始结点和 q 次新建，可以预留至少 n+q 个真实槽位，另留空编号或哨兵。声明长度为 CAP 的数组合法下标是 0～CAP−1；分配前要检查容量。

value[id] = 新数据;
nxt[id] = 后继编号;  // 两个字段属于同一个结点

05 / 30A · 从零到单链表

遍历与查找：顺着线走到哪里停

这一站带走：建立先判断、再访问、再前进的循环。

先修：第 3～4 站

找不到也是一种正常结果。

遍历要按顺序访问每个活跃结点。先令 cur 指向 head；只要 cur 不是 0，就访问它，再沿 nxt 前进。查找则多一个停止原因：当前值已满足要求。

cur = head;
while (cur != 0) {
    // 访问当前结点
    cur = ______;  // 沿哪一条箭头走？
}

“查找第一个值为 x 的结点”，返回结点编号；找到末尾仍未命中，返回空编号 0。空表从一开始就不能进入访问。若改成查找第 k 个结点，需要增加“已经走过几个”的角色，不能把 k 当成编号直接使用。

不带环的链中，每次前进一步，最多访问 n 个结点。因此遍历与最坏情况查找都为 O(n)，不是因为结点能按编号访问就变成 O(1)。

06 / 30A · 从零到单链表

创建：头插、尾插与空表

这一站带走：知道每次新建后，入口与尾巴怎样变化。

先修：第 4～5 站

一张张放到最前面，读出来会反过来。

依次读入 10、20、30。每次把新结点接到队首叫头插：先让新结点连向原来的 head，再更新 head。尾插则把新结点接在末尾，通常维护 tail，避免每次都从头找尾巴。

对空表做第一次尾插是特别的一步：还没有旧尾巴，不能让不存在的 tail 指向新人；需要同时建立 head 与 tail。以后每次尾插，新结点后继为 0，旧尾巴指向新人，最后移动 tail。

要维护的承诺创建过程中的检查
head 指向第一个活跃结点空表 head=0
tail 指向最后一个活跃结点非空时 nxt[tail]=0
输入顺序按要求保留先用三张不同值卡片验证

维护 tail 的尾插总共 O(n)。若每次尾插都遍历旧链找尾，工作量为 0+1+…+(n−1)，总共 O(n²)。同样叫“创建”，实现方式不同，代价就不同。

编号是找卡片的线索，地址也是。

    Node* next;
};
// 认识字段即可；不是完整解题程序。
Node* u = new Node{7, nullptr};

p->value 读取 p 指向结点的数据，等价于 (*p).value；使用前必须保证 p 指向仍存活的结点。Node* q=p; 只是复制地址，两根指针可能指向同一结点，没有新建一张卡片。

入口 → A → B → C ↑ ↓ └───────┘

如果链意外形成了环

不变式：结果链已按序排列；所有尚未处理的结点仍能从两根入口找到；结果尾巴指向已接入部分的最后一位。某条链空了以后，另一条剩余部分可以整体接上。真实搬的是链接，不必新复制数据结点。

合并两链共访问至多 n+m 个结点，O(n+m) 时间；迭代局部链接可用 O(1) 额外空间。链表归并排序先分半、切断中间链接，递归分别排序，再合并。切断很关键：只记住中点，不会让左链自动变短。

与递归课件相接

递归边界至少要处理空链与单结点；两结点必须真正分成 1+1。链表归并排序可做到 O(n log n) 时间；递归栈通常为 O(log n)，还需算清合并过程是否递归。

重新连链时，不允许结果尾部留下无意的回路。两个输入若共享结点，本节前提失效，应先处理共享关系，不能照搬合并。

并查集维护每个活跃连通块大小，合并时更新最大值。每次 Q 记录当前最大值，全部结束后把记录的回答顺序倒回来。注意这里是原位置连续：不能因为双链里 1 与 3 相邻就把它们当作没有缺口的一段。

删除可以撤销：先记下改变了什么

这一站带走：用栈保证恢复时的环境正确。

先修：第 12、21 站；栈、回溯的“做与撤销”

撤销最后一步，先让世界回到它发生前的样子。

双链允许两种操作：删除一个活跃结点；撤销最近一次尚未撤销的删除。删 u 前记录 (u,p,q)，p 与 q 是那一刻的邻居，再跨接 p 与 q。把这条记录放到栈里。

撤销时取栈顶，把 u 放回 p 与 q 之间。为什么可以相信这两位邻居还适合接回？因为后发生的删除已经先撤销，环境沿时间倒退回来了。前提是期间只有这种受控删除及其逆序恢复，没有任意插入、移动或清空。

教练备课 / 尝试后核对

核对例：H↔A↔B↔C↔T，先删 B 再删 A。若先恢复 B，它记录的左邻 A 仍不活跃，会断开正确入口；先恢复 A，再恢复 B，才与原状态一致。空间记录每个未撤销动作 O(1)，q 次操作共 O(q)。不要释放还要恢复的结点；数组槽位也不能提前复用。

这是搜索回溯中“试一种选择→探索→撤销”的基本功。可以把记录扩展成“改了哪个字段、原值是多少”的修改栈，从而逆序恢复多个字段。它仍不是任意历史版本的数据结构。

这一站带走：用同一套链接思想组织多条邻接表。

先修：第 4～7 站；图的顶点与边概念

每个城市各有一个入口，串起它发出的道路。

图里一个点可以连向多个点。给每个顶点 u 一个 head[u]，记录它第一条出边的编号；给每条边 e 记录 to[e]、nextEdge[e]。这里链接串起来的是边记录，不是顶点队伍。

约定边编号从 1 开始，0 表示没有边。加入 u→v 时，把新边头插到 u 的边链：新边终点为 v，后继为旧 head[u]，再更新 head[u]。因此同一顶点的遍历顺序通常与加入顺序相反。

变量角色
u当前顶点编号
e当前边编号
to[e]这条边的终点顶点
nextEdge[e]同一出发点的下一条边
head[u]顶点 u 的第一条出边

遍历从 e=head[u] 开始，沿 nextEdge 直到 0。不能写成 e=to[e]，那会把顶点编号误当边编号。无向边通常存两条有向边，因此容量至少按 2m 条边计算；全部邻接表遍历 O(n+m)，不是每个点都扫描所有 m 条边。

链表思想帮你理解图的存储。图搜索中的“访问过”标记与链中结点活跃状态不是同一职责，应另设变量。

堆 + 链表：最近邻候选会过期

这一站带走：区分局部邻接维护与全局最优选择。

先修：第 21 站；优先队列、比较规则、懒删除

堆里那张旧通知，说的邻居可能已经变了。

教学模型：有序位置 x₁<…<xₙ。每步选当前相邻且距离最小的一对，把二者都删除；距离相同选左位置更小的一对；直到不足两点。双链告诉你谁相邻，小根堆负责从候选中选最小距离。

初始化把 n−1 对相邻者入堆。弹出 (距离,u,v) 后先验证：u、v 都活跃，且 nxt[u]=v；否则这条候选已过期，丢弃继续弹。删掉一对后，只可能新增“原左邻 L 与原右邻 R”这一对，把它入堆（两者必须都是真实活跃结点）。

L ⇄ u ⇄ v ⇄ R → L ⇄ R

别把“曾经相邻”当作“现在仍相邻”。本模型位置不变、结点不恢复，因此活跃与相邻检查足够；若权值会变化或编号会复用，还要比较版本号或当前代价。

初始化 O(n) 对候选，每次有效删除最多新增一对，总入堆 O(n)，每条最多弹出一次，总 O(n log n)、空间 O(n)。若题意改成“选若干对使总收益最大”，按当前最小距离选择是否正确要另证明。本模型的顺序是题目规定，不能偷换成未经证明的贪心结论。

按值删点，按位置计贡献

这一站带走：从最近边界推导子数组最值贡献。

先修：第 21 站；排序、贡献法、乘法计数、64 位整数

操作顺序按值排，链上的顺序仍按位置排。

综合模型：数组中各值互异，求所有非空连续子数组的最小值之和。直接枚举每个子数组很慢；换成问“aᵢ 会作为多少个子数组的最小值”。左右第一个比它小的位置记为 L、R，没有则取 0、n+1。

用从 1 开始的位置编号。若 aᵢ 是某段最小值，左端必须在 L+1～i，右端必须在 i～R−1。两边可独立选择，所以贡献为 aᵢ·(i−L)·(R−i)。先自己画出可选端点，再用公式，不能凭记忆直接套。

怎样用链表找到这些边界？先按原位置建双链，再按数值从大到小依次删点。处理 i 时，较大的值已删除；其余活跃值都比 aᵢ 小，所以链上的最近邻居恰是所需 L、R。先记贡献，再删 i。

教练备课 / 尝试后核对

互异例 [3,1,2]：处理 3 的位置 1，边界 0、2；处理 2 的位置 3，边界 2、4；最后处理 1 的位置 2，边界 0、4。贡献分别为 3、2、4，总和 9。排序 O(n log n)，链操作总 O(n)，空间 O(n)。乘法从第一步就转 long long，并依据 n 与值域检查 64 位是否足够。

重复值是一个新的分配问题

[2,2] 的长度 2 子段不能被两位都认领。可给 (值,原位置) 定义唯一顺序，让相等时左侧位置优先作为最小值，再按这个关键字降序删除。此时边界语义变成左侧 ≤、右侧 <；左右不能同时取严格或同时取非严格。单调栈也能求这些边界且做到线性，但要重新证明弹栈条件。

第一行 n（1≤n≤2×10⁵），第二行严格递增的 n 个整数位置 xᵢ（−10⁹≤xᵢ≤10⁹），原编号 1～n。反复删除当前相邻且距离最小的一对，距离相同时选左端原编号更小的一对。直到不足两点。输出 ⌊n/2⌋ 行，每行是被删对的原编号，左、右依次输出。n=1 时没有输出行。

先手推坐标 [0,2,3,10,11]，写每轮全部候选，再设计算法。目标 O(n log n)；距离与排序规则使用足够宽的整数类型。用全扫描慢程序验证小数据。

调试与方法卡：证明这条链真的完整

这一站带走：用可达性、不变式和对拍形成可靠习惯。

先修：前面已完成的站点；随机测试可选学

看起来像链，还要经得起双向检查与边界测试。

先分类：编译错误看语法与类型；卡住看循环是否推进、是否误造环；崩溃先查越界、空指针、释放后访问；结果不对则找手推与程序第一次分叉的位置。不要一出错就整份重写。

结构证据能发现的问题
线性链访问到终止位置；调试时记录 seen自环、长环、错的结束标记
从入口可达的真实结点数 = size漏接结点、孤立结点；size 本身也需可靠更新
双链每个有效相邻关系互相一致只改了一个方向
正向序列 = 反向序列的逆序首尾更新或逆向链接错误
映射只指向活跃且值相符的结点值删掉后残留旧身份
每轮与朴素 vector 模型比较复杂操作顺序错误

对拍时用很小的 n 随机生成合法操作，简单 vector 版本用插入、删除与扫描作裁判，复杂度可以慢但逻辑要独立。每次操作后就比较完整编号序列，不能只比最后输出。失败时保存随机种子与操作前缀，再逐条删减到最小反例。

调试检查遍历整条链可能 O(n)，适合小样本验证；正式大数据运行时不要在每次操作后一直全链检查，把 O(1) 操作无意变成 O(n)。学习环境允许时，地址与未定义行为检测工具也能辅助发现内存问题。
