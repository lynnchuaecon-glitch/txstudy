先看谁该先取出，再认识栈和队列

这一站带走：从撤销和排队两个例子，认识两种不同的取出顺序。

先修：数组、循环、条件判断

在画图软件里，你先画了 A，再画 B，最后画 C。按一次“撤销”，应该先去掉刚画的 C；再按一次，才去掉 B。软件需要记住画过哪些笔画，并且每次先取出最近画的那一笔。

换成窗口排队：A 最早来，B 接着来，C 最后来。窗口空出来时，应该先叫 A，再叫 B。虽然也是依次记下 A、B、C，这次却需要先取出最早加入的那一个。

为了按这些规则保存和取出数据，程序可以使用不同的容器。这里的“容器”指保存数据并提供放入、查看、取出操作的工具。每次先取最近加入者的，叫栈；先取最早加入者的，叫队列。

例子依次加入 A、B、C 后先取谁对应规则
撤销笔画C，然后 B，最后 A栈：后进先出
按到达顺序叫号A，然后 B，最后 C队列：先进先出

怎样从题目选到工具？仍看撤销：要保存的是“已经画出的笔画”，新画一笔就加入，按撤销时取出最近一笔。先把这三个动作说清楚，才知道栈的规则正好适合它。栈负责按顺序交出笔画记录；根据记录把画面恢复，仍要由程序完成。

还有一种规则可以先作比较：若任务编号 8、2、5 依次到来，题目却要求“每次处理编号最小的任务”，就应该先取 2。它既不是最近来的，也不是最早来的。这种按大小或其他优先级取数据的工具叫优先队列，第 8 站再与普通队列对照。

停下来，轮到你完成

把“撤销最后一笔画”“按到达顺序叫号”“每次取编号最小的任务”分别配上工具。用编号为 8、2、5 的三张卡依次放入，验证三种规则各会先取谁。

尝试后仍卡住 · 提示一

只问下一次必须取谁，不先问 C++ 名字。

只在需要时 · 提示二

先来先服务与最小值先服务，可能选到不同对象。

三类自测

  • 最小：一个对象。
  • 区分：A、B、C 先后进入后连续取两次。
  • 边界：一个对象也没有时请求取出。
家长／教练核对 · 请先让孩子尝试

分别对应栈、普通队列、优先队列。必须区分“没有对象”与“对象的值为 0”。空容器没有合法的顶或首元素。

栈：只能从这一端放，也从这一端拿

这一站带走：手推入栈、查看与出栈的区别。

先修：数组、循环、条件判断

想象桌上叠着三张卡：最下面是 A，中间是 B，最上面是 C。规定只能从上面放，也只能从上面拿。此时必须先拿走 C，才能拿到 B。这就是栈的“后进先出”。最上面可以操作的位置叫栈顶，最下面叫栈底。

放一张卡叫入栈，拿走最上面的卡叫出栈。还有一个不同的动作叫查看栈顶：只读出 C，卡片仍然留在原处。查看后再查看，看到的还是 C；出栈后再查看，才会看到 B。

下面的实验为了方便显示，把卡片横着排，最右边当栈顶。方向换了，规则没有变：只从最右边放入或拿走。如果已经没有卡片，就不能再查看或出栈；程序需要先判断是否为空，再决定如何回应。

停下来，轮到你完成

按“放 A、放 B、查看、取出、放 C、取出、取出、再取出”手推；每一步记录栈内容、是否真的删除，以及空栈时怎样回应。

尝试后仍卡住 · 提示一

查看后，下一次查看是否还看到同一个对象？

只在需要时 · 提示二

取空栈不是取到了某个默认值。

三类自测

  • 最小：放入一项后查看两次。
  • 区分：交替放入与取出。
  • 边界：开始为空；取完后再次取；取完后再加入。
家长／教练核对 · 请先让孩子尝试

两次查看都应是同一顶元素，直到真正出栈。示例按栈取出依次是 B、C、A，最后一次空栈。实验可切换队列比较同一输入的不同结果。

用数组搭一个栈：top 到底表示什么？

这一站带走：选择一种约定并贯穿全部操作。

先修：数组、循环、条件判断

现在用数组的格子保存这些卡片，格子从 0 编号。为了知道哪些格子正在使用，我们用一个整数 top 记录栈里目前有几个元素。开始没有元素，所以 top=0。

例如依次放入 6、8 后，st[0]=6、st[1]=8，top=2。最上面的元素在下标 1，正好是 top−1；下一个新元素要放进下标 2，正好是 top。因此本讲中，top 同时也是下一次写入的位置。

加入 x 时，先写入 st[top]，再把元素个数加 1。出栈时，把 top 减 1，就表示最后一格不再使用。例如刚才的栈出栈后 top=1；下标 1 的格子即使还留着 8，它也已经不属于当前栈。以后加入新数，可以覆盖这格。

用区间写法表示，当前使用的是 [0,top)：包含下标 0，不包含下标 top。查看栈顶前要确认 top>0；写新元素前要确认还有空格。有些资料把 top 定义成“栈顶的下标”，那是另一套约定；本讲始终把它当元素个数。

停下来，轮到你完成

用容量为 4 的数组实现入栈、查看、出栈；先写出 top 的登记表，再追踪有效区间，不要求把出栈后旧格子清零。

尝试后仍卡住 · 提示一

有效数据是哪几格，由数值为零决定，还是由 top 决定？

只在需要时 · 提示二

只有一个元素时，数量和最后一个下标分别是多少？

三类自测

  • 最小：加入 0，不能当作空栈。
  • 区分：放入 3、7，弹出后放入 9。
  • 边界：空栈操作、容量刚好用满、尝试超容量。
家长／教练核对 · 请先让孩子尝试

第二组最终为 [3,9]，top=2。超容量操作不能写数组外；本地工具可返回失败，具体竞赛题则按题目约束设计容量。

交给标准库前，先翻译每个动作

这一站带走：把手工栈的放入、查看和删除，对应到标准库操作。

先修：数组、循环、条件判断

第 3 站里，我们自己用数组和 top 管理栈。C++ 标准库已经提供了这种工具：包含 <stack> 后，可用 std::stack<int> st; 声明一个存整数的栈。你仍要决定何时放入、何时取出，只是不必自己管理数组位置。

几个操作分别对应刚才的动作：st.push(x) 放入 x；st.top() 查看栈顶；st.pop() 删除栈顶。st.empty() 判断是否为空，st.size() 取得元素个数。

查看与删除仍是两件事。假设栈顶是 6，你想把它取走并记到变量 x 中，应先在非空时读取 top()，把 6 保存下来，再执行 pop()。pop() 只负责删除，不会把被删的 6 当作返回值交给你。

// 只展示查看并保存这个局部动作
if (!st.empty()) {
    int x = st.top();
    // 此时栈没有变化。若题目要求取走，还需要哪个动作？
}

括号匹配：最近打开的，必须先关上

这一站带走：用栈保存尚未匹配的左括号。

先修：数组、循环、条件判断

先看 [()]。读到左方括号 [ 时，它还在等右方括号；随后读到左圆括号 (，又打开了里面的一层。读到 ) 时，应先关上最近打开的圆括号，之后的 ] 才能关上外面的方括号。

所以，我们可以把尚未配对的左括号放进栈：每读到一个左括号就入栈。读到右括号时，先看栈顶是不是与它同类的左括号。相同就删除栈顶，表示这一对已经配好；不同就说明关闭顺序或类型不对。若栈本来就是空的，这个右括号也没有对象可配。

字符串读完后，还要再检查一次：栈里若仍有左括号，表示还有括号没有关闭。例如 (() 的右括号可以配对，但读完仍留下一个左括号，因此整串仍不合法。

每次查看栈时，都把里面的内容读成“还在等右括号的左括号”。已经配好的一对要移除，之后才能处理更外面的一层。

停下来，轮到你完成

手推 ([)] 与 ([])，找出第一次不同的匹配动作；随后独立写判断器，并列出它判失败的全部原因。

接回递归与撤销：谁还没有完成？

这一站带走：复用栈模型解释暂停和恢复。

先修：栈；函数调用与局部变量

函数调用时，也会出现“最近开始的任务先完成”。假设 A 执行到一半调用 B，B 又调用 C：此时 A 在等 B，B 在等 C。C 完成后，应先回到 B 刚才暂停的地方；B 完成后，才能回到 A 继续。

可以给每次调用画一张工作单，上面记下参数、局部变量，以及调用结束后从哪里继续。A 的工作单先放下，B 放在它上面，C 最后放上去。C 完成就拿走 C 的单子，露出仍在等待的 B。这正好符合栈的取出顺序，叫作调用栈。

画图软件的撤销也需要这样的记录。例如把圆从位置 2 移到位置 5，若想撤销，记录中需要保留旧位置 2；只记“移动过圆”还不够。栈解决的是先恢复哪一条记录，记录里保存的信息则决定能否真正恢复旧画面。

继续阅读：递归中的调用栈；链表删除与撤销。

队列：轮到最早等待的人

这一站带走：用队首和队尾保存先来先服务的过程。

先修：数组、循环、条件判断

排队时，新来的人站在队尾，下一位被叫到的人在队首。A、B、C 依次加入后，先服务 A；此时若 D 来了，剩下的顺序是 B、C、D。查看队首只是看看下一位是谁，出队才把这一位从队伍中移除。

用数组 q 保存队伍时，可以不搬动后面的人，而是用两个整数记录位置：head 指向第一位等待者，tail 指向下一位加入时要写的空格。开始都为 0；加入一人就写 q[tail]，然后 tail 加 1；服务完一人就让 head 加 1。

例如 A、B、C 入队后，head=0、tail=3；A 出队后，head=1、tail 仍是 3。此时等待者在下标 1、2，共 tail−head=2 人。已经服务过的下标 0 不再算入队伍。若三人都出队，就有 head=tail=3，表示队伍已空。

把这段有效位置写成 [head,tail)，意思是从 head 开始，到 tail 之前为止。这个简单版本不回头使用旧格子，因此容量要够放入所有曾经入队的元素。怎样重复使用旧格子，第 9 站再学。

如果学过链表：队列和链表有什么关系？

队列说的是“谁先取出”：队尾加入，队首取出。链表说的是“数据怎样连接”：每个结点记下后一个结点在哪里。刚才我们用数组实现了队列，也可以用链表实现同样的入队、出队规则。两者回答的是不同问题，还没学链表可以跳过这段。

停下来，轮到你完成

普通 queue 与优先队列，不能互相冒充

这一站带走：把先进先出的完整模拟落到代码。

先修：数组、循环、条件判断

第 7 站用数组和两个下标实现了排队。也可以让 C++ 标准库代管这些存储细节：包含 <queue> 后，用 std::queue<int> waiting; 声明一个整数队列。

waiting.push(x) 让 x 入队，waiting.front() 查看队首，waiting.back() 查看队尾，waiting.pop() 删除队首。waiting.empty() 判断是否为空，waiting.size() 取得人数。查看和删除都需要先确认非空；与栈一样，pop() 只删除，不返回被删的值。

普通队列不按数值大小插队。8、2、5 依次入队，普通队列先取 8，因为它最早到。若题目要求先取最小值，就应使用按这个优先级工作的工具，叫优先队列。《贪心探险》里会进一步讲它。

现在用普通队列完成一个小模拟器：第一行给出操作次数 q，接着每行是一条 IN x、OUT 或 FRONT。IN x 加入 x；OUT 输出并删除队首；FRONT 只输出队首。初始队列为空，空队遇到 OUT 或 FRONT 都输出 EMPTY。这里 q 记录操作次数，waiting 保存等待中的数据。

循环队列：把用过的格子再利用

这一站带走：按排队顺序取人，同时重复使用数组的旧格子。

先修：数组队列；取余

有 3 个数组格子，编号 0、1、2。放满三个人后，即使最早的那个人已经离开，第 7 站的 tail 也还在向右走。我们希望再次利用空出来的格子，于是把 0、1、2 想象成一个圈：走过 2 后，下一格回到 0。这叫循环队列。

容量记为 C，从位置 pos 走到下一格，可写成 (pos+1)%C。head 仍指向第一位等待者，tail 仍指向下一次写入位置。注意，尾部绕回 0，只是存储位置变了；新加入的人仍排在所有等待者之后。

这个版本再用 size 记录人数：size=0 表示空，size=C 表示满。为什么需要它？以 C=3 为例，开始 head=tail=0；连续放满三人后 tail 绕回 0，head 也仍是 0。两次下标相同，一次却空、一次却满，人数才能把它们区分开。

因此，加入前先确认 size<C，再写入并移动 tail、增加人数；出队前先确认 size>0，再移动 head、减少人数。本讲只用这一套人数约定。

  • 区分：容量 3 回绕后，应按 B、C、D 取出。
  • 边界：队满拒绝加入；队空拒绝取出。

队列接搜索：为什么近的一层先出来？

这一站带走：理解等步长 BFS 中的待处理顺序。

先修：普通队列；二维数组与网格边界

在网格上找最少要走几步，可以先找“一步能到哪里”，再找“两步能到哪里”。下面每次只能上下左右走一格，不能进入障碍；每一步的花费相同。

列 1列 2列 3
行 1起点空地障碍
行 2空地空地终点

先把起点放进队列，记距离为 0。取出起点后，把它旁边能走且还没发现的格子加入队尾，记距离为 1。接下来取出一个距离为 1 的格子，再把从它新发现的邻居记为距离 2，加入队尾。

为什么距离为 1 的格子能先处理完？因为它们先进入队列，而新发现的距离为 2 的格子只能排在队尾，不能插到它们前面。于是搜索会一层一层向外走，这叫广度优先搜索，简称 BFS。

一个格子可能从两个方向到达。第一次发现它时就标记“已发现”，随后再从别处遇见它，就不重复入队。这里队列保存的是“已发现、还没检查邻居的格子”。只有每一步花费相同时，按层数先到才能直接说明步数最少。

单调栈：把还在等答案的位置记下来

这一站带走：从具体目标理解删掉哪些候选。

先修：栈与下标；时间复杂度

任务是：对每个数，找它右边第一个严格比它大的数的位置。看 [3,1,4]：读到 3 时，右边还没读，先记下它的位置；接着的 1 不比 3 大，3 还要等，1 也开始等待。

把这些等待的位置依次放进栈，最新的 1 在栈顶。读到 4 时，4 比 1 大，1 的答案就找到了，可以把 1 的位置出栈。露出的 3 也小于 4，它同样找到了答案。两者在之前都没有遇到更大的数，因此这次找到的是“第一个”。

一般地，读到新数后，反复比较它与栈顶位置对应的数：新数更大，就记录那个位置的答案并出栈；直到栈空或新数不再更大，才把新位置入栈。栈里保留下来的数从底到顶不会变大，这种保持大小顺序的栈叫单调栈。

我们保存下标，是为了知道“给哪个位置填写答案”，也能据此读取数值。相等不算严格更大，不能因此出栈。读到末尾仍在栈里的位置，说明右边没有更大值，按题目要求记录“没有”。每个位置只入栈一次、最多出栈一次，总操作量随 n 成比例，记作 O(n)。

“删数字”也会用到单调栈，但它删除元素的理由不同。先讲清正在找什么，再决定何时出栈。

单调队列：只留下还可能成为窗口最大值的数

这一站带走：在滑动窗口最大值中维护候选。

先修：普通队列；双指针固定窗口；双端操作

长度为 k 的窗口向右移动，每次要找窗口里的最大值。先看一个局部过程：旧数 2 还在窗口里，右边新来了 5。以后只要窗口仍包含这个 2，也一定包含更靠右的 5；而 5 更大、离开窗口也更晚。因此只求最大值时，可以不再把 2 当候选。

另一个删除理由是“离开窗口”。例如窗口左端已经移过某个数的位置，即使它很大，也不能再算在当前窗口里。我们既要比较大小，又要检查位置，因此用一列候选下标记录可能的最大值。

这列下标需要两端都能删除：从前端去掉已经离开窗口的旧下标；新数到来时，从后端反复去掉值不大于它的候选，再把新下标放到后端。这样的工具叫双端队列 deque。普通 queue 只能从队首删除，不能完成这里的后端删除。

处理完后，候选值从前到后递减，因此队首就是当前最大值；要等窗口凑满 k 项，才输出本窗口答案。若当前右端下标是 r，窗口左端就是 r−k+1，比这个下标更小的位置已经离开。每次删除时，都应能说清是“出了窗口”，还是“被后来的更大或相等值替代”。

这里只要求最大值；相等时保留较新的位置足够。如果题目还要求最早出现的位置，相等时的处理就要重新考虑。

  • 区分：[4,1,3,2]、k=2。
  • 边界：全相等、严格下降、k=n。
