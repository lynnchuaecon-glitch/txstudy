专题 01｜复杂度第 1/2 页 · 例子讲解

01.1　先把 8 张卡片摆出来，再谈“快不快”

假设桌上有 8 张卡片，你想找出最大的数字。先把第一张作为目前最大数，再从第二张起逐个比较。这里的“工作”，是一次比较，不是代码写了几行。

如果卡片增加到 16 张，还是用这个办法，就要多看大约一倍的卡片。增加到 100 张，也只是按同样方式继续看下去。我们关心的是：数据变多时，工作量怎样跟着变多。

先把每一轮真正做的次数写出来

办法8 张卡片时16 张卡片时变化
从第二张起与目前最大数比较7次比较15次比较数据翻倍，工作约翻倍
每张都与每张比较一次8×8=6416×16=256数据翻倍，工作变4倍
每次把剩余范围缩成一半8→4→2→116→8→4→2→1数据翻倍，只多缩一次

第三行先数的是“缩小次数”。实际查找是否还要检查最后那一张，要看代码；但“多一倍数据，只多一轮”的增长特点不变。

现在才给这些增长方式起名字

第一种记作 O(n)，第二种记作 O(n²)。第三种的轮数接近“2 乘多少次才到 n”，这个次数叫以 2 为底的对数，记作 log₂n。因为 2×2×2=8，所以 log₂8=3。

O 不是秒数，也不是精确次数
O(n) 表示工作量至多按 n 的某个常数倍增长。n−1、2n、3n+5 在本阶段都按线性量级看。比较两个 O(n) 程序时，仍可能一个快一个慢；机器、常数与实现细节并没有消失。

所以不要先问“这题应该背哪个 O”。先找一个需要反复做的动作，列出数据变多后它做几次，再把这个趋势写成符号。

专题 01｜复杂度第 2/2 页 · 整理与练习

01.2　复杂度：数工作量，不数代码行数

这一节要弄懂什么
题目问“多快、多占空间”时，先确定 n 指什么，再看它变大后要多做多少事。

把循环翻译成工作量

动作次数或总量常用量级
从 1 数到 nn 次O(n)
1、2、4、8……直到超过 n每次翻倍；n=16 时只需几步O(log n)
外层 n 次，内层每次 n 次n × nO(n²)
第 i 轮做 i 次1+2+…+nO(n²)
每层总工作 n，约 log₂n 层n × log₂nO(n log n)
算式规则
先后执行的工作量相加，保留增长最快的一项；真正嵌套且独立的次数相乘。两层循环不一定是 O(n²)，如内层从当前指针继续向前，总移动也可能只有 n 次。

时间与空间分开问

时间看累计做多少事；辅助空间看同一时刻最多额外保留多少东西。输入数组本身通常不计入辅助空间；递归栈、临时数组要计入。

for (int i = 1; i <= n; i *= 2) {
    // 一次固定大小的工作
}

本讲义的运算次数估计默认整数运算 O(1)、数值不溢出；高精度专题另按位数计。若原题问平均、最好、最坏情况，必须分别回答。

02.1　递归里的“另一个自己”，究竟拿走了什么任务？

我们先只做一个很小的任务：计算 1+2+3+4。你当然可以直接加；现在换一个分工方式，目的是看懂递归怎样工作。

约定 S(n) 负责“算出从 1 加到 n 的和”。那么 S(4) 可以留下最后的 4，把前面的 1+2+3 交给 S(3)。只要 S(3) 把自己的任务完成，S(4) 再加上 4 就行。

S(4) 的整份任务：1+2+3+4
交出去的部分：1+2+3　　自己留下的部分：4

这不是随便把答案叫作 S(3)。我们已经给 S(3) 规定了明确职责，它只需要解决一个同样的、但更小的问题。

先把任务交下去，上一层先等着

这一层留下什么等待谁
S(4)最后还要加4S(3) 的结果
S(3)最后还要加3S(2) 的结果
S(2)最后还要加2S(1) 的结果
S(1)直接知道答案是1不再交出任务

到了 S(1)，不需要再交给别人。它把 1 交回 S(2)，S(2) 算出 2+1=3；再交给 S(3)，得到 3+3=6；最后 S(4) 得到 4+6=10。

最容易漏掉的动作
调用下一层时，这一层还没完成。它保留着“回来后还要加几”这张便条。下一层返回后，要回到原来暂停的位置继续，不能当成整份程序重新开始。

“从大任务交到小任务”是去程，“把小任务答案逐层带回来”是回程。递归表达式写得短，是因为它把这两段过程藏在调用和返回里了。

02.2　递归：把同一种小任务交给下一层

这一节要弄懂什么
先理解一次调用承诺完成什么，再看它怎样交出更小任务。递归不是“代码长得像函数套函数”。

三个问题组成一张递归说明卡

问题求 1+2+…+n 的例子
这次调用负责什么？S(n) 返回前 n 个正整数的和
最小任务直接怎么办？S(1)=1
怎样交出更小任务？S(n)=n+S(n−1)，下一层负责前 n−1 个数
分清“去”和“回”
S(4) 等 S(3)，S(3) 等 S(2)，S(2) 等 S(1)。到最小任务后，把结果逐层带回来。每一层的 n 是这一层自己的参数。
S(4) = 4 + S(3)
             S(3) = 3 + S(2)
                          S(2) = 2 + S(1)
                                       S(1) = 1

终止条件写了，也必须真的走得到

若只在 n==0 时返回，却总调用 f(n+1)，从正数出发就越走越远。检查“终点”与“每次朝终点推进”是两件事。

专题 03｜递归追踪第 1/2 页 · 例子讲解

03.1　一层一个便条：为什么返回后还能记得自己的 n？

仍看求和，但把一行想象成三个动作。下面只是函数内部的局部片段，假设 n>1：

int small = S(n - 1);  // 先等小任务完成
int result = n + small;
return result;

S(4) 调用 S(3) 时，不是把同一个 n 从 4 改成 3。新的调用有自己的参数 n；上一层的 n=4 仍留着。否则回来时，它就不知道还应加几。

便条①：n=4，等 S(3) 回来，接着算 4+small
便条②：n=3，等 S(2) 回来，接着算 3+small
便条③：n=2，等 S(1) 回来，接着算 2+small
便条④：n=1，直接交回 1

最后放上去的便条，先处理完

n=1 的那层先返回，n=2 才能继续，随后是 n=3、n=4。这种“后放上去，先取下来”的管理方式，就是递归调用栈。先把便条过程理解清楚，再记“栈”这个词。

如果 cout 写在调用前，它会在去程执行；写在调用后，它要等下一层完成后才执行。于是同一个 n 可能在两个不同时刻输出。

动作别和什么混在一起
cout << n在屏幕上留下一个数字，不等于把它交给上层
return result把结果交给调用者；不会自动打印
函数被调用一次新建一层任务；这层可能打印0次、1次或多次
看图数空间
最深处有4张尚未全部返回的便条，就要同时容纳4层。若之后还有另一条分支，不要把已经返回并撤掉的旧便条再次算入“同时占用”。

03.2　递归追踪：输出、返回值、调用次数是三件事

这一节要弄懂什么
读代码时先圈出题目到底在问什么，避免把树的深度当调用总数，把屏幕输出当返回值。
void walk(int n) {
    if (n == 0) return;
    cout << n << " ";    // 下去前做
    walk(n - 1);
    cout << n << " ";    // 回来后做
}
walk(2) 的时刻发生的事
进入 n=2先输出 2，等待 walk(1)
进入 n=1先输出 1，等待 walk(0)
进入 n=0直接返回，不输出
回到 n=1，再回 n=2分别执行各自后面的 cout
数时间与数栈的方法
在调用树上，每出现一个函数调用就画一个节点；时间看整棵树的节点和节点内工作。空间看最长的未返回路径，不把所有分支同时相加。

同样是“递归”，成本可能很不同

调用方式（每次其余工作 O(1)）时间递归栈
只调用一次 f(n−1)O(n)O(n)
只调用一次 f(n/2)O(log n)O(log n)
调用两次 f(n−1)O(2ⁿ)O(n)

三柱汉诺塔就是“搬走上面 n−1 个 → 移动最大盘 → 搬回 n−1 个”。移动次数满足 M(n)=2M(n−1)+1，M(1)=1，因此为 2ⁿ−1；栈深只随 n 线性增长。

运算符左右两边都调用会输出的函数时，不应凭书写顺序断定 C++ 的求值顺序。本页用分开的语句明确先后；原卷相关问题见家长附录。

专题 04｜递归优化第 1/3 页 · 例子讲解

04.1　为什么同一个 F(3) 会被算两遍？

斐波那契数列规定 F(0)=0、F(1)=1，后面每项是前两项之和。这个关系本身没有问题，慢的地方出在我们怎么执行它。

假如直接把每次 F(n) 都展开成 F(n−1)+F(n−2)，F(5) 的工作单会这样分开：

F(5)
├─ F(4)
│  ├─ F(3)
│  └─ F(2)
└─ F(3)  ← 这个参数前面已经出现过

两份 F(3) 的答案明明相同，但普通函数调用不会因为名字和参数相同，就自动记得上一次结果。每份都继续拆出自己的 F(2)、F(1)，于是重复越来越多。

给已经做完的任务留一个登记格

格子空着时填过后
memo[3]F(3) 尚未算好保存 F(3) 的答案
memo[4]F(4) 尚未算好保存 F(4) 的答案

第一次需要 F(3)，照常把它算完，然后填入 memo[3]。以后又遇到同一个任务，先查格子，已经填过就直接取走结果。这个办法叫记忆化。

为什么不能只说“加个数组就快了”
数组存的是“哪个状态已经求完、答案是什么”。必须先查，再决定是否计算；算完后还要登记。只有数组声明，没有这套使用过程，不会减少重复。

对于这份数列，一共只有 0…n 这些不同参数。每个新状态的加法只算一次，因此固定宽度运算下工作量变成 O(n)。但递归仍可能一路走到最小参数，调用栈并没有因为记忆化就自动消失。

保存nextSaved=Y记住当前结点的旧后继
反向X.next改为空（prev）X成为已反转部分的末端

前进cur改指向Y继续处理保存的后半段

第二轮后：已反转 Y→X→空　｜　未处理为空

双向扫描的一种常见版本

以首元素为基准，右指针先找小于基准的值，左指针再找大于基准的值，未相遇时交换。相遇后再把首位置的基准交换到相遇位置。每次移动都带上 i<j 的保护。

在“首元素作基准、相遇后与首元素交换”的这套代码里，扫描次序参与保证相遇位置合适。先左后右并不是逐字替换就能保持正确。试 [1,2] 即可发现问题。

另一种：单向扫描维护分区边界

以末元素为基准，i 表示“小于基准区”的末尾，j 遍历尚未分类的元素。找到小值时扩张小值区，再交换进去。最后基准放在 i+1。

Hoare 类划分、首元素归位版、末元素归位版并非同一套边界。不要把某题的 i≤j、另一题的 i<j 和递归区间混用。

21.1　快排为何退化：划分是否平衡很重要

这一节要弄懂什么

两棵递归树，成本不同

划分形态每层与层数结果
大致分成两半每层合计 O(n)，约 log n 层平均时间 O(n log n)

有序数组配合“总选首元素”为基准，容易出现第二种形态。选中间位置不代表选中了数值中位数；随机基准或三数取中可改善常见表现，但不是消除最坏情况的保证。

26.1　从1000减去1：借位怎样一格一格传过去？

先规定A≥B，使用一个变量borrow记录“低一位向本位借走了1”。借位不凭记忆直接跳过一串0，而是在每一位都执行相同的动作。

本位先算t=a[i]−b[i]−旧borrow。若t<0，就向更高一位借1，当前差加10，新borrow设1；否则不再借，新borrow设0。本位结果保存调整后的差。

1000−1 的本位先扣旧借位是否继续向高位借保存的数字 / 新borrow
个位：0−10−1−0=−1需要，加109 / 1
十位：0−00−0−1=−1需要，加109 / 1
百位：0−00−0−1=−1需要，加109 / 1
千位：1−01−0−1=0不需要0 / 0

暂存结果[9,9,9,0]表示0999。最高的多余0去掉后是[9,9,9]，输出999。三个0不是被一次神秘操作变成9，而是连续三轮都发现“本位还欠一个”。

为什么减数读完了，还不能结束？

减数1在个位就读完了，但borrow仍是1。如果直接复制A剩下的十、百、千位，就把这笔借位债忘掉。要处理完A的所有位，缺失的减数位按0参与。

一个借位变量已经够，不要又重复减数组
采用borrow法时，借位通过下一轮减borrow体现；若同时把a[i+1]减1，下一轮又扣borrow，就扣了两次。直接改数组和记录borrow是两种表示，不能不加区分地叠用。

结果为0时，也要保留一个0；不能把所有零删到数组为空。完成后用“差+减数=被减数”核验，借位过程中还应检查最终borrow是否回到0。

T01 · 复杂度：数工作量，不数代码行数

应看到的证据：i 为 1、2、4、8、16，共 5 次；嵌套内层 n 次，总体 O(n log n)，不是 O(log n)。

卡住时：先让她写出实际 i 值，检查她数的是轮数还是内层总工作。

T02 · 递归：把同一种小任务交给下一层

应看到的证据：F(n)=n!；F(0)=F(1)=1；F(n)=n×F(n−1)。4→3→2→1，回传 1、2、6、24。

卡住时：若只会写乘法，追问 F(3) 替 F(4) 完成了哪一部分。

T03 · 递归追踪：输出、返回值、调用次数是三件事

应看到的证据：输出 3 2 1 1 2 3；共 4 次调用；含基例时最大同时 4 层。时间、栈空间均 O(n)。

卡住时：让她在“调用下一层”处画等待标记，返回后从下一句继续。

T04 · 递归优化：相同的事别重新算

应看到的证据：重复版 1+2+4+8=15 次，复用版 4 次；两者最长路径均 8→4→2→1，为 O(log n)。

卡住时：先问她两次相同表达式究竟有没有一个变量替它保存结果。

T05 · 数论起点：约数、倍数、素数与奇偶

应看到的证据：1 两者皆非；2、53 为素数；9、49 为合数。53 只需排除 2、3、5、7。25 是反例。

卡住时：若她漏 49，重点是为什么试除上界包含等号，而不是多做几次除法。

T06 · GCD 与 LCM：铺方砖和再次相遇

应看到的证据：(12,18)→(18,12)→(12,6)→(6,0)，GCD=6；再次同时闪是 LCM=36 分钟。

卡住时：若一开始 a<b，她应能发现首次取余为 a，下一次自然交换到大数在前。

T07 · 质因数分解：种类、次数与约数个数

应看到的证据：90=2×3²×5；3 种；3 出现 2 次；约数个数 2×3×2=12。

卡住时：让她给三个“数量”分别写名字，避免正确算出了另一个问题。

应看到的证据：差 24；大于 1 的正约数为 2、3、4、6、8、12、24，恰为所求模数。

T09 · 埃氏筛：用素数划掉它的倍数

应看到的证据：如 12、18、24 同时被 2 和 3 标记；6 已被 2 标记，9 是 3 尚需处理的最早倍数。

卡住时：不要只接受“因为效率高”，需要她说出前面的倍数为什么已被处理。

T10 · 线性筛：让每个合数只登记一次

应看到的证据：p=2 标记 12，6%2==0 后停止；若继续 p=3 会标记 18，但它应由 i=9、p=2 生成。

卡住时：要求她把“i 的因子”和“i×p 的最小质因子”分开说。

T11 · 链表：数据盒子之间用箭头相连

应看到的证据：p 从 7 结点移动到 4 结点，随后该结点数据改成 6；head 和 next 链接均未变。

卡住时：若她把箭头也改了，回到“p 变量”和“p 指向的结点的 next 字段”两个盒子。

T12 · 链表插入：接好新结点，再改旧入口

应看到的证据：先保留 B 的原前驱 A；S.next=B，S.prev=A，再 A.next=S、B.prev=S。顺序可有多种，只要使用旧指针前不覆盖它。

卡住时：不用要求背唯一顺序，让她在每一步之后重画箭头检验。

T13 · 链表删除：先绕过去，再释放

应看到的证据：cur 始终先留在 dummy，连续删除两个 5 后才越过 8；最终 dummy.next 指向 8。否则可能漏掉第二个 5。

卡住时：聚焦 cur 是“前驱”这个角色，别把它当正在删除的人。

T14 · 循环、反转与快慢指针：先说明停止的原因

应看到的证据：第一轮后 prev=A、cur=B；第二轮 prev=B、cur=C；第三轮 prev=C、cur=空；新链 C→B→A。必须先存旧 next。

卡住时：这里讲反转服务于箭头角色理解，不要求立刻写完整模板。
