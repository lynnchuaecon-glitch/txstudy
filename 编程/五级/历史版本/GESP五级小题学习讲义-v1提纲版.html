复杂度：数工作量，不数代码行数

这一页解决什么
题目问“多快、多占空间”时，先确定 n 指什么，再看它变大后要多做多少事。

把循环翻译成工作量

动作次数或总量常用量级
从 1 数到 nn 次O(n)
1、2、4、8……直到超过 n每次翻倍；n=16 时只需几步O(log n)
外层 n 次，内层每次 n 次n × nO(n²)
第 i 轮做 i 次1+2+…+nO(n²)
每层总工作 n，约 log₂n 层n × log₂nO(n log n)
算式规则
先后执行的工作量相加，保留增长最快的一项；真正嵌套且独立的次数相乘。两层循环不一定是 O(n²)，如内层从当前指针继续向前，总移动也可能只有 n 次。

时间与空间分开问

时间看累计做多少事；辅助空间看同一时刻最多额外保留多少东西。输入数组本身通常不计入辅助空间；递归栈、临时数组要计入。

for (int i = 1; i <= n; i *= 2) {
    // 一次固定大小的工作
}

本讲义的运算次数估计默认整数运算 O(1)、数值不溢出；高精度专题另按位数计。若原题问平均、最好、最坏情况，必须分别回答。

递归：把同一种小任务交给下一层

这一页解决什么
先理解一次调用承诺完成什么，再看它怎样交出更小任务。递归不是“代码长得像函数套函数”。

三个问题组成一张递归说明卡

问题求 1+2+…+n 的例子
这次调用负责什么？S(n) 返回前 n 个正整数的和
最小任务直接怎么办？S(1)=1
怎样交出更小任务？S(n)=n+S(n−1)，下一层负责前 n−1 个数
分清“去”和“回”
S(4) 等 S(3)，S(3) 等 S(2)，S(2) 等 S(1)。到最小任务后，把结果逐层带回来。每一层的 n 是这一层自己的参数。
S(4) = 4 + S(3)
             S(3) = 3 + S(2)
                          S(2) = 2 + S(1)
                                       S(1) = 1

终止条件写了，也必须真的走得到

若只在 n==0 时返回，却总调用 f(n+1)，从正数出发就越走越远。检查“终点”与“每次朝终点推进”是两件事。

sin(sin(x)) 是嵌套调用；仅凭外面又写了一次函数名，不能说明 sin 的函数体在调用自身。递归可以直接调用自己，也可以经其他函数间接回到自己。

递归追踪：输出、返回值、调用次数是三件事

这一页解决什么
读代码时先圈出题目到底在问什么，避免把树的深度当调用总数，把屏幕输出当返回值。
void walk(int n) {
    if (n == 0) return;
    cout << n << " ";    // 下去前做
    walk(n - 1);
    cout << n << " ";    // 回来后做
}
walk(2) 的时刻发生的事
进入 n=2先输出 2，等待 walk(1)
进入 n=1先输出 1，等待 walk(0)
进入 n=0直接返回，不输出
回到 n=1，再回 n=2分别执行各自后面的 cout
数时间与数栈的方法
在调用树上，每出现一个函数调用就画一个节点；时间看整棵树的节点和节点内工作。空间看最长的未返回路径，不把所有分支同时相加。

同样是“递归”，成本可能很不同

调用方式（每次其余工作 O(1)）时间递归栈
只调用一次 f(n−1)O(n)O(n)
只调用一次 f(n/2)O(log n)O(log n)
调用两次 f(n−1)O(2ⁿ)O(n)

三柱汉诺塔就是“搬走上面 n−1 个 → 移动最大盘 → 搬回 n−1 个”。移动次数满足 M(n)=2M(n−1)+1，M(1)=1，因此为 2ⁿ−1；栈深只随 n 线性增长。

运算符左右两边都调用会输出的函数时，不应凭书写顺序断定 C++ 的求值顺序。本页用分开的语句明确先后；原卷相关问题见家长附录。

递归优化：相同的事别重新算

这一页解决什么
看懂记忆化与快速幂的共同点：已经算出的结果能否复用。函数名字叫“快速”不代表真的快。

斐波那契：重复的是同一个状态

F(5) 需要 F(4) 和 F(3)，而 F(4) 又需要 F(3)。朴素递归会重新展开同一个任务。记忆化用表保存“这个参数的答案是否已经算过”。

实现时间（按固定宽度运算）辅助空间
朴素 F(n−1)+F(n−2)指数级，常用上界 O(2ⁿ)O(n) 栈
记忆化：每个状态只求一次O(n)O(n) 表与栈
从小到大递推，只保留前两项O(n)O(1)

快速幂：先算一半，再复用

long long half = power(x, n / 2);
// n 为偶数：使用 half * half
// n 为奇数：还要多乘一个 x
同一个子任务写两次，不会自动替你缓存
若写成 power(x,n/2) * power(x,n/2)，算法分析要计两次调用。一个减半子调用是 O(log n)；两个相同减半子调用的总节点数是 O(n)。

递归可以改成非递归，复杂过程可用显式栈模拟，简单过程可直接循环。不保证所有递归都会被编译器自动优化；尾调用优化也不是 C++ 必须提供的保证。

数论起点：约数、倍数、素数与奇偶

这一页解决什么
把名词变成可以检查的定义，避免把“奇数”和“素数”、“约数”和“质因数”混为一谈。
概念意思例子与边界
d 是 n 的约数n 能被 d 整除3 是 12 的约数，12 是 3 的倍数
素数（质数）大于 1，正约数恰有 1 和自身2 是唯一的偶素数
合数大于 1，除 1 与自身还有其他正约数9 是奇数，但不是素数
1只有一个正约数既不是素数，也不是合数
互质两个正整数的最大公约数为 18 与 9 都不是素数，却互质

为什么试除只需到平方根？

如果 n=u×v，u、v 不可能都大于 √n。因子成对出现，至少有一个不大于 √n。等于平方根的那一格不能漏，例如 49。

边界要能解释
判断一个数是否为素数：先处理 n<2，再尝试可能的因子。对较大正整数，d <= n/d 可以避免 d*d 的乘法溢出。

奇偶性是便宜的第一层过滤

偶±偶为偶，奇±奇为偶，奇±偶为奇；乘积只有“两数都是奇数”时才是奇数。大于 3 的素数必为 6k±1，但反过来不成立，例如 25。

GCD 与 LCM：铺方砖和再次相遇

这一页解决什么
能从现实含义区分最大公约数与最小公倍数，再追踪辗转相除中的两项变化。

两种问题，两种“共同”

长方形用同样大的正方形无缝铺满，最大边长对应 GCD；两盏灯分别每 a、b 分钟闪一次，同时闪后再次相遇的时间对应 LCM。

当前 a当前 ba%b下一对
301812(18,12)
18126(12,6)
1260(6,0)
为什么余数能替换大数
若 a=q×b+r，那么 a、b 的任何公约数也能整除 r；b、r 的公约数也能整除 a。所以 gcd(a,b)=gcd(b,r)。余数一直变小，直到为 0。

当采用“b==0 返回 a”的版本，最后一对是 (g,0)；若采用“a%b==0 返回 b”的版本，会早一层结束。调用序列依代码终止条件而定。

对正整数：gcd(a,b) × lcm(a,b) = a × b

实现时常先除再乘：a/gcd(a,b)*b，并选择足够宽的类型。先除能减小中间数，但结果过大仍会溢出；用 long long 也不是无限大。

辗转相除时间通常记为 O(log min(a,b))；循环版辅助空间 O(1)，递归版还要计同阶的调用栈。

质因数分解：种类、次数与约数个数

这一页解决什么
先分清题目数的是“不同因子种类”还是“某个因子出现次数”。

把合数拆到每一块都是质数

72 = 2 × 2 × 2 × 3 × 3 = 2³ × 3²

不同质因数有 2 种；质因子按重复计算共有 5 个；因子 2 的指数是 3。唯一分解定理说的是：大于 1 的整数分解为质数乘积，忽略顺序后唯一，允许重复。

试除时，剩余数也会变
找到一个因子 d 后要反复除，直到不能整除。每次除掉的是这一种因子的一个副本。试除结束后，若剩余数大于 1，它本身就是还没记录的质因子。
记录对象72 的记录常见混淆
不同质因数{2,3}不能看到一个 2 就计一种新因子
每个质因数的次数2:3 次，3:2 次不能只除一次就跳走
正约数个数(3+1)(2+1)=12质因数不是所有约数

约数为什么有这么多？

72 的约数可选 0、1、2、3 个因子 2，再选 0、1、2 个因子 3，共 4×3 种组合。枚举约数时 d 与 n/d 成对；完全平方数的平方根只算一次。

试除到平方根的质因数分解，按固定宽度整数运算计可给 O(√n) 上界。成功除因子的次数合计至多 O(log n)，不等于每个候选都除这么多次。

同余与模运算：余数相同，差能整除

这一页解决什么
理解“模 m 同余”的含义，并知道取模能保留哪些运算关系。此项由考纲明确要求。

同一圈上的同一位置

把时钟看作长度为 m 的圆圈，走 a 步与走 b 步停在同一位置，就有 a≡b (mod m)。对非负整数，等价于 a%m=b%m；也等价于 m 整除 a−b。

29 与 17 模 6 同余：两者余 5，差为 12
运算（m>0）可用关系
加法(a+b) mod m = ((a mod m)+(b mod m)) mod m
减法可先做余数相减，再调整到 0…m−1
乘法可先取模再相乘取模，但中间乘积也要防溢出
除法不能直接把普通除法照搬到模运算中
C++ 的负数余数
-1 % 5 为 -1；想把一个整数余数规范到 0…m−1，可使用 ((x % m) + m) % m，前提是类型足够容纳中间计算。

数位和为什么能帮助判断被 9 整除？

10 模 9 余 1，100、1000 也一样。所以一个十进制数模 9 与各位数字之和模 9 相同。这个规则不能直接搬到“模任意数”。

埃氏筛：用素数划掉它的倍数

这一页解决什么
一次要找很多素数时，把“每个数分别试除”改成“从一个素数出发批量排除”。

在 2…30 的数表上做三件事

  1. 最初把 2 起的数暂记为可能是素数，0、1 单独排除。
  2. 遇到还没被标记的 i，它是素数；把 i 的合数倍数划掉。
  3. 继续向后看，留下的就是素数。
素数 i从 i² 开始划掉较小倍数在哪里处理了
24、6、8、10……从 4 开始
39、12、15、18……6 已经是 2 的倍数
525、30……10、15、20 已有更小质因子
为什么从 i² 开始
小于 i² 的合数倍数 i×k 满足 2≤k<i，k 至少有一个更小的质因子，它先前已使这个数被标记。起点 i² 减少重复，但埃氏筛仍可能重复标记某个合数。
for (long long j = 1LL * i * i; j <= n; j += i) {

快排为何退化：划分是否平衡很重要

这一页解决什么
区分“平均很快”“最坏保证”“稳定性”。名字里有“快”不能作为推理依据。

两棵递归树，成本不同

划分形态每层与层数结果
大致分成两半每层合计 O(n)，约 log n 层平均时间 O(n log n)
每次分成 0 和 n−1n+(n−1)+…+1最坏时间 O(n²)

有序数组配合“总选首元素”为基准，容易出现第二种形态。选中间位置不代表选中了数值中位数；随机基准或三数取中可改善常见表现，但不是消除最坏情况的保证。

稳定性是另一件事

算法快慢讨论工作量，稳定性讨论相等关键字的先后顺序。改变选基准方式不会自动让普通快速排序变稳定。

递归栈也随划分变化：平均 O(log n)，最坏 O(n)。因此“划分原地进行”不等于整个递归算法额外空间严格为 O(1)。

贪心在做什么？

每步按一个规则挑当前最有利的选择，并把它固定下来，通常不回头枚举所有方案。例如按最便宜优先买商品、按最早结束安排活动。
