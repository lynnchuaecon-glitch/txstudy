出发：先说清“最好”是什么意思

这一站带走：分清目标、限制和方案；知道题目要优化哪一个量。

探险队有很多选择，但“最好”是哪一种，要由任务决定。

同样是选活动，可能要求“参加最多场”，也可能要求“获得最多积分”。选了很多场，不一定积分最高。写算法前，先用自己的话说清楚：我要让什么尽量大，或者尽量小？哪些规则不能违反？

要说清的事例如：下午安排活动
输入每场活动的开始与结束时间
限制一个人不能同时参加重叠的活动
目标参加的活动场数最多
输出一个最大场数，或题目要求的活动名单

先认识三个词

方案是一次完整安排，例如选择哪几场、按什么顺序参加。可行表示没有违反规则。最优表示在所有可行方案里，目标值最好。最优方案可以不止一份。

找到一份能参加的安排，只证明“做得到”；要说“最多”，还要说明别的安排不能更好。贪心算法要解决的，就是怎样在某些问题里，做一连串有依据的选择，得到最优结果。

会比较两个数、写 if 和循环、使用数组，足够开始。排序会在第 6 站复习；优先队列和栈会在需要时解释，不要求先学过。

02 / 22营地 A / 认识选择

第一次贪心：每次拿最便宜的

这一站带走：从一个可以证明的简单选择，认识局部选择与整体目标。

有若干张贴纸，只想买到恰好 k 张，不挑图案，每张最多买一次。怎样让总价最少？

先用价格 [7,2,5,3]，k=2 手推。你可以列出所有两张组合，也可以尝试：每次从剩下的贴纸中选最便宜的一张。这种规则只决定眼前这一步，却希望最后总价最好。

“贪心”的准确含义

按一条局部选择规则逐步构造方案，是贪心的基本想法。关键不是“总选大的”或“总选小的”，而是局部规则是否保证整体目标。规则还没证明时，只能称作候选策略。

为什么这里可以选便宜的？

如果某份方案选了一张较贵贴纸，却没选某张更便宜贴纸，把贵的换成便宜的：张数不变，每张最多一次的规则也没破坏，总价不会变大。反复这样换，就能得到选最便宜 k 张的方案。

条件一变，要重新想
如果题目要求“每种图案至少一张”，或者“买某张能让另一张打折”，刚才的交换可能破坏条件或改变其他价格。不能把这条规则搬过去就用。

这个例子展示了一种常用理由：就算别人给出一份最优方案，我们也能把它换成按这一步贪心选择的样子，而不会更差。第 5 站会把这件事讲清楚。

第一次反例：眼前省，不等于最后省

这一站带走：用一个小反例推翻不可靠的贪心规则。

凑够一笔钱，想用最少枚硬币。“每次拿不超过剩余金额的最大硬币”，一定正确吗？

先约定每种硬币数量无限，必须恰好凑够。试试面值 1、3、4，目标金额 6。先按最大面值规则走完，再想有没有另一种凑法用了更少硬币。不要只看第一枚减少了多少金额。

实验室 / 一条看似合理的规则

先写出最大面值规则会怎么凑。演示结束后，再与小规模穷举得到的最少枚数比较。

反例只需要一个，支持例子却不够多

一组合法输入上策略失败，就足以推翻“这条策略对所有合法输入都正确”。反过来，十组、一百组都成功，也不自动构成证明。演示中的小规模穷举用于核对这些输入，不代替一般性的证明。

找反例时，可以先让一个大面值“差一点凑不齐”，再看看两个中等面值是否更合适。把数值缩小、把物品减到两三种，往往比盯着大样例更有帮助。

别从一个反例推到另一个极端
这说明最大面值策略不适用于任意硬币系统，不是说所有找零钱问题都不能贪心。具体面值结构可能支持另一份证明。

写一张贪心任务卡

这一站带走：把目标、选择、状态变化和安全理由连起来。

先把这一步到底在选什么说清楚，再讨论如何写循环。

任务卡需要写的内容
目标与约束最大化或最小化谁？哪些条件不能破坏？
候选与规则现在有哪些可选项？用哪个量比较？相同怎样处理？
当前状态已经选了什么？剩余什么？下一次选择依赖哪几个量？
安全理由为什么可以这样选，不会失去全部最优方案？
推进与停止做完选择，哪个变量变化？何时没有工作可做？

例如活动安排中，状态可以是“最后一场已选活动的结束时刻”；每接受一场就更新它。若程序的状态只记“看到了第几个活动”，却没记录时间限制，后面就没法判断冲突。

贪心与循环、递归不是同一层的词

贪心描述“怎样作决策”；循环与递归描述“怎样组织执行”。贪心常用循环，也可以用递归表达。看见排序、循环或一次扫描，不能据此认定它一定是贪心。

常见贪心会固定一个安全决定，继续处理剩余任务；后面也会遇到用堆调整暂定集合的做法。它不穷举所有历史分支，而是保持一个经过证明的选择规则。

05 / 22营地 A / 认识选择

怎样证明：把“感觉不错”变成理由

这一站带走：理解交换论证、保持领先与循环不变量的作用。

贪心真正困难的部分，通常是解释：为什么这一步不会堵死通向最优的路？

方法一：交换，但要交换得合法

设别人给出一份最优方案 O，而它的第一步和我们的贪心选择 G 不同。我们尝试把 O 中的一部分换成 G，然后检查两件事：限制有没有被破坏？目标有没有变差？

若都没问题，就说明至少有一份最优方案包含 G。固定这一步，再解决同类型的剩余任务，才形成完整证明。并不要求每一份最优方案原本都选 G。

方法二：每走一步，都不落后

活动安排中，可以比较“选完同样多场后，谁结束得更早”。如果我们的时间边界始终不晚，就不会比对手更早失去后续活动机会。比较量要与后续可选范围直接相关，不能随便拿一个数字称为“领先”。

方法三：保持一句始终为真的话

例如“已经处理过的需求，都被所选位置覆盖”。这句话叫不变量，帮助验证状态更新与循环。但只证明已经覆盖，不等于证明用了最少位置；最优性仍需交换或下界等依据。

一份完整的小证明
① 存在最优方案包含本次选择；② 做完选择后的任务定义正确；③ 继续使用规则仍满足条件；④ 最小或空任务能结束。只说“第一步最好”不够。

06 / 22营地 A / 认识选择

排序：把选择规则交给程序

这一站带走：理解排序键、相等情况与严格比较，知道排序本身不保证贪心正确。

如果每一步都要选“剩下最便宜”，先排好顺序，后面就容易找了。

排序键就是比较时看的量：价格、开始时间、结束时间、重量、单位价值……不同的键，对应不同候选策略。先决定规则并解释理由，再写比较函数。

// 局部阅读与填空：活动按结束时间由小到大
bool cmp(const Activity& a, const Activity& b) {
    if (a.end != b.end) return ___;
    return a.start < b.start;
}
// 补的是比较规则；不是整题代码。

比较函数要“严格”

同一个对象与自己比较，应当为 false。升序通常用 <，不能为了照顾相等写成 <=。还要保证规则一致：不能出现 a 应在 b 前、b 在 c 前、c 又在 a 前的循环偏好。

是否需要第二排序键，要由题目决定。若相同结束时间选谁都不会影响最大场数，可以用开始时间或编号让结果稳定；若题目规定字典序等额外目标，就必须把它纳入证明。

先比较，别随便做减法或除法

用 a.x - b.x < 0 比大小，减法可能先溢出。比两个分数时，浮点误差或整数除法也可能改变顺序；第 12 站会用交叉相乘，并检查乘法范围。

n 个元素排序通常需要 O(n log n) 时间，再扫描一次通常 O(n)。但比较函数若本身很慢，还要计入每次比较的成本。

07 / 22营地 B / 证明与经典模型

匹配：把刚好够用的留给合适的人

这一站带走：用排序与双指针完成最大匹配，并解释为何跳过或消耗。

每个孩子最多拿一块饼干，饼干大小达到孩子的需求就算满足。怎样满足尽量多的人？

孩子需求为 [2,4,5]，饼干大小为 [1,3,5]。先在纸上连线，每块饼干只能连一个孩子。目标是满足人数，不是让某个人拿到最大饼干。

把两边从小到大排序。每次看需求最小的未满足孩子，以及最小的未使用饼干。饼干太小，连这个孩子都满足不了，也满足不了后面需求更大的孩子，可以跳过。若够用，就把它给这个孩子。

为什么“够用就给”安全？

两端配对：最重的人先有安排

这一站带走：在至多两人的限制下，证明轻重配对使船数最少。

每艘船最多坐两个人，总重量不超过 L。所有人都要过河，怎样用最少的船？

先保证每个人体重都不超过 L，否则题目无解。将体重排序，盯住当前最重的人 H 与最轻的人 S。

  • 若 H+S>L，连最轻的人都不能与 H 同船，H 只能独自乘一艘。
  • 若 H+S≤L，可以让 H 与 S 同船，再处理剩下的人。

能一起坐，为何不会影响别人？

考虑一份最优安排。如果 H 与 S 已同船，无需改变。若它们分属两艘船，可以把 H 与 S 放一起：如果原来分别还有同伴 X、Y，把 X 与 Y 配到一起也不会超重，因为 Y≤H，而原来 X+H≤L；若原来的某艘只有一人，剩下的人也能在原来的船数内安置。

优先队列是一种按优先级取数据的容器。你告诉它比较规则，放进元素后，每次取优先级最高者。普通排队按先来后到；这里按你规定的重要程度。值越小越优先，就是常说的小根堆用途；值越大越优先，就是大根堆用途。

操作含义使用前检查
push(x)加入候选 x候选是否有资格进入
top()查看当前最优先的元素，不删除非空
pop()删除当前最优先元素，不返回该值非空；需要它的值就先保存 top
empty() / size()判断空、查看元素个数空时不能取或读顶端

原来的每堆是一片叶子；每次合并新画一个父节点，两个被合并的堆是孩子。一个原始石子堆会被计费多少次，等于它到最终根节点经过多少次合并，也就是深度。因此总花费等于各原始重量 × 各自深度的总和。

一个较大的重量若放得更深，会更频繁地被重复计费。对固定树形，把较小重量放到较深位置不会更差。

想清楚了再看 · 为什么可以先合并最小两堆？

任一完整二叉合并树，都能找到一对位于最深层、同一个父节点的叶子。把两个最小重量交换到这两个位置：若小重量 x 原来更浅，深处重量 y≥x，交换带来的变化为 (x−y)×(深度差)，不大于 0。

因此存在一棵最优树让两个最小重量成为最深的一对兄弟。把这对兄弟缩成重量 x+y 的一片叶子，剩下仍是同类合并问题；原总代价等于缩小问题的总代价再加 x+y。继续对缩小问题采用相同选择，形成证明。

每次取最小两个，合并后放回候选集合。新堆可能比原来某些堆更小，也可能更大，所以只把最初数据排序一次然后随意邻接合并并不够。用小根堆可在 O(n log n) 时间、O(n) 空间完成。

若原来只有一堆，不需要合并，代价是 0。若题目限制只能合并相邻堆，上面交换叶子的位置可能破坏顺序，这条算法不再能直接套用。

有些选择可以先放进计划，发现装不下时，再按规则替换。这里调整的是计划，不是把已经做完的事撤销。

每个任务都耗时 1 天，有正整数截止日 d 和非负整数收益 p。所有任务从第 1 天就可做，每天最多完成一个，只能在截止日当天或之前做完，目标是收益总和最大。允许不做某些任务。

先按截止日升序看任务，把收益放进小根堆暂留。处理截止日为 d 的任务后，若暂留数量超过 d，说明前 d 天装不下，移除当前收益最小的一个。若未超过，就继续保留。

实验室 / 保留的计划可以调整

任务 A(截止1,收益20)、B(2,10)、C(2,40)、D(3,15)、E(3,30)。先预测遇到 C 时，是否应该因为前两天已满就直接跳过它。

可行性要检查所有较早截止日

把保留任务按截止日排，编号第 j 个必须满足 j≤它的截止日。仅仅看“总任务数不超过最大截止日”不够：两个任务都截止第 1 天，即使另有任务截止第 100 天，也不能把前两个都做完。

按截止日依次处理时，之前这些较早约束已经满足。新任务的截止日为当前 d，它不会增加比 d 更早的任务数；删除一个保留任务也不会破坏旧的可行性。因此“加入后必要时删一个”仍能维持全部约束。

为什么删最小收益？

当前这 d+1 个暂定任务中，至少有一个不能保留。删最小收益对这次冲突造成的损失最少。但这句话还需要与“早期约束不被破坏”合在一起，才能成为整体算法的依据。

提高思考 / 为什么整个计划也最优？

可以用“把收益分成一层层”来核对，不必只凭删最小的直觉。收益为 3 的任务，给第 1、2、3 层各贡献 1；收益为 1 的任务只给第 1 层贡献 1。于是总收益等于每一层被选任务数的总和。

固定任意一个门槛 h，只看收益≥h 的任务，问最多能选几个。按截止日处理，设前面最多能留 C 个。来了一个收益≥h、截止日为 d 的新任务，最多数量变成 min(C+1,d)：旧任务最多贡献 C 个，前 d 天最多装 d 个；若 C<d，就把新任务排在旧计划后一天，能做到 C+1；若 C=d，就保留原来的 C 个。收益低于 h 的新任务不影响这个数量。

再观察本章算法：新任务低于 h 时，若超额，它或另一个更低收益者会被删，高收益任务数不变。新任务不低于 h 时，若当前高收益数 C<d，即使总数超额，也必定还有一个低于 h 的任务可删，高收益数增加 1；若 C=d，加入后全是高收益任务，删一个后仍是 d 个。

所以，对于每一个门槛 h，算法都恰好保留了能安排的最多个高收益任务。每一层都已达到可行上限，把各层相加，总收益就达到上限。这也说明早先舍弃的任务不会在未来变成必须找回的选择。

这个论证依赖所有任务恰好一天、都从第 1 天可做、收益非负。分层只是用来证明，不需要程序真的循环到最大收益。

收益堆维护的是保留集合，不是实际执行顺序。若还要输出计划，保存编号，最后按截止日安排保留任务。排序与堆操作共 O(n log n)，空间 O(n)。

为什么每次加最多的？

当必须再增加一次停车时，同样来自已可达范围、同样花一次停车，取更多油能让覆盖范围不更小，也不会减少后续能够触及的站。把方案中的较小补给替换成这次最大补给，或在较大补给原本也被使用时调整其使用次序，可以保持不更多的停车次数与不更差的可达性。

这是出发前制定计划的算法。堆保存“我们本来可以在哪些站停车”的机会；后来选中较早站，表示把它纳入计划。最终将选中的站按位置顺序执行即可，不是在途中瞬间回到旧站。

删数字：把更好的前缀留下

这一站带走：从栈操作理解局部替换与字典序，控制删除次数。

给一串十进制数字，恰好删除 k 位，保持剩余数字的相对顺序，让结果最小。

先规定 0≤k≤字符串长度。选完后去掉前导零作为显示形式；若空了或全为零，输出 0。比较候选时，它们都保留同样多的位数，所以可以从左到右找第一处不同，数字更小的候选更好，这就是这里使用的字典序。

需要一个能撤掉末尾的容器

栈只在一端加入、移除，操作端叫栈顶。这里把“当前保留前缀的末尾”作为栈顶：新数字从左往右读入，必要时删掉当前前缀的最后一位，再放入新数字。查看栈顶前先判非空。

先用三张纸卡认识栈

把容器画成一排格子，只在最右边操作。先放 1，再放 4，再放 3，成为 [1,4,3]，右端 3 是栈顶。拿走一次，只能拿走 3，剩下 [1,4]，新的栈顶是 4；不能隔着 3 直接拿走中间的 4。这就是“后进先出”。

在 C++ 中可以用 string st 保存数字字符：st.push_back(c) 放到末尾，st.back() 查看末尾，st.pop_back() 删除末尾。后两者都先用 !st.empty() 确认非空。容器本身不决定删谁，下一段的贪心规则才决定何时删除。

若还有删除额度，且末尾数字比新来的大，删掉这个较大的末尾，可以让更小的数字更早出现。只要条件继续成立，可以接连删除；相等时不要为了变小而白白删除。额度用完以后，剩下数字直接接上。

实验室 / 前缀怎样被一步步调整

每一步预测：是删栈顶，还是把新数字放到末尾？同时追踪还剩几次删除额度。

为什么从前面改善？

等长数字串比较时，前面第一处差异决定大小。只要可以删除前面的较大数字，让后来的较小数字来到这里，比保留较大者再在更后面省数字更有利。删除后，新的相邻末尾仍要重新比较，所以用 while，而不一定只用一次 if。

若读完还有删除额度，说明还能删的保留前缀没有形成必须向前改善的下降处，此时从末尾删，保住更靠前的较小数字。最后才处理前导零，避免把去零误计为题目要求的删除动作。

这个过程常叫单调栈贪心：在仍有删除额度时，尽量维护非递减前缀；额度耗尽后，最终栈不保证整体有序。不要为了强行有序而多删。

每个数字最多入栈一次、出栈一次，即使代码里有 while，总操作仍为 O(n)，存储 O(n)。很长的数字串不必转成整数。
